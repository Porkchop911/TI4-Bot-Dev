## The recurring failure modes, in order of how often they bit

1. **A module arrives correct, tested, and called by nothing.** Six times: combat, invasion,
   fleet, production, leaders, agenda effects. A unit test proves a module *works*, never that
   anything *uses* it. `wiring.rs` exists for this; **add to it whenever you wire something**.
2. **The corpus is not what memory says.** `electType` is null on every agenda; `requirements`
   is the literal string `"null"`; the space-dock secret wants 3 docks not 4; an alias I was
   sure of (`usc`) does not exist. Every one was caught by a test asserting *every registered
   alias is a real card*. **Write that test for any new registry.**
3. **Duplicate options are not free.** A sampling decider draws per option, so a move written
   three times is three times as likely as an equally good one written once. This bit in the
   choice model, cargo, move options, casualties, sustain, action-card discards, and payment
   plans. Dedup by what makes two things *genuinely different* — damage, source planet, printed
   name — not by list identity.
4. **Test fixtures that pass for the wrong reason.** A hex ring is itself a route, so "block the
   centre" only bites at move 2; "two systems apart" is not "opposite". Cost three attempts
   across two modules before `fixtures::Hub::across` fixed it in one place.
