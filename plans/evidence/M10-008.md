## Implementation

### `play_batch()` in `rollout.rs`
- Takes `&[PlayerId]`, `&BTreeMap<PlayerId, Profile>`, `&[u64]` seeds
- Divides seeds into chunks by `available_parallelism()`
- Each chunk processed by one scoped thread
- Results sorted by seed after collection (deterministic regardless of completion order)
- Profiles cloned per thread (cheap — Arc under the hood)
- Empty input returns empty vec

### `train()` in `stage1.rs`
- Changed from sequential `.map(|seed| play(...)).collect()` to `play_batch(&seeds, ...)`
- Removed unused `play` import

## Known limitations
- No configurable worker count — uses `available_parallelism()` by default. A `workers` field can be added to `Plan` if needed.
- No progress reporting during batch execution.
- No persistent worker pool (M10-015). Each generation spawns new threads.
