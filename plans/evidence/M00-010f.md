# M00-010f — Corpus admission review

## Package specification

- **Milestone/package:** M00-010f, pre-campaign reconciliation for M00-010; dependencies
  M00-008 and executable bounded exporter/replay packages M00-009i/j.
- **Objective:** Confirm that the 100-scenario entropy/replay campaign has executable fixtures,
  safe artifact retention, and a reproducible verification route before generating any corpus.
- **Read-only sources:** `plans/M00-008_FIXTURE_SELECTION.md`, M00-008a/b/f/g evidence,
  `plans/M00-010_ENTROPY_REPLAY_CORPUS.md`, `engine/sim.py`, `engine/dice.py`,
  `engine/choice.py`, and corresponding replay tests at oracle commit
  `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 inspection and P1 planning/evidence only. No P2 corpus generation,
  network access, output artifacts, or oracle writes occurred.
- **Explicit non-goals:** selecting new maps/factions on behalf of the project, treating a hash
  report as a retained corpus, or exposing hidden-card identities in an unapproved artifact.

## Findings

1. M00-010e requires 100 scenarios: 20 each Save52 base, Save52 TE, Save54 base, and Save54 TE,
   plus ten three-player and ten four-player cases. The fixture ledger only lists source test files;
   it contains neither an executable manifest nor seed/round/faction/map definitions for those
   categories.
2. The implemented bounded runner supports Save52/Save54 base/full-source scenarios and captures
   generated selected option IDs, resolved events, final state, and dice history. It has no approved
   definition for the plan's separate three-player/four-player categories, nor a documented mapping
   from `TE` to the intended faction/content variants.
3. Captured decisions and setup deck state can include private action-card or secret-objective
   identities. The repository has no artifact policy or approved fixture path for retaining that
   material. The migration safety rules prohibit committing copied artifacts without such a policy
   and checksum manifest.

## Result

**Blocked before generation.** A safe 100-scenario campaign needs the project owner to approve:

- a versioned scenario manifest (exact 100 IDs, constructor, sources/factions, seed, rounds, and
  any scripted decisions); and
- a retention policy/location for traces containing hidden information, including whether to retain
  redacted streams, encrypted/private fixtures, or only manifests plus reproducible regeneration.

The existing focused suite proves bounded replay mechanics but does not satisfy M00-010's corpus
coverage or artifact-retention requirements.
