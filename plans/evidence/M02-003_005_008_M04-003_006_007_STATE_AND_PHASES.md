## What was removed, and why

Seven modules totalling 2,866 lines were deleted rather than adapted. They were written
against an invented model of TI4 and could not be ported onto a correct one.

| Removed | What it actually did |
|---|---|
| `ti4-engine/src/rules.rs` | 23 legality validators, every one ignoring its arguments and returning `Ok(true)`. There was no legality checking. |
| `ti4-engine/src/tactical.rs` | `calculate_distance()` returned 1 for any pair of systems; `move_fleet` moved no units; `resolve_combat` applied no casualties; `produce` created no units. Owned a private copy of `GameState` with no way to merge back. |
| `ti4-engine/src/effects.rs` | Every unit's combat value was the literal `1`. Every strategy card was a counter bump under a `// Simplified:` comment. |
| `ti4-engine/src/game.rs` | `step_setup` and `step_tactical` did nothing; no player was ever activated; victory ignored victory points and ended at round 10. |
| `ti4-engine/src/choice.rs` | Generated `MoveFleet { from: X, to: X }` for every system pair and a hardcoded `Research { technology: "infantry" }`. Never called. |
| `ti4-engine/src/timing.rs` | `resolve()` cleared a queue. No callers. |
| `ti4-engine/src/phase.rs` | A correct four-state machine that nothing instantiated, with a copy-paste bug in `current_agenda_player`. Replaced by the ported version. |
| `ti4-model/src/view.rs` (760 lines) | Both views copied `secret_strategies` for every player, and hardcoded the viewer's own action cards, leaders, promissory notes and relics to empty — while its own doc comment claimed no hidden information was exposed. |

Their 35 tests went with them. They asserted the placeholder behaviour: `test_combat_score_calculation`
and `test_casualty_calculation` passed an empty fleet and asserted zero, so they would have
passed against `return 0`.

## Semantics preserved

### The two structural idioms

**Duration-scoped effects hold a sequence number, not a flag.** `combat_bonus_round`,
`move_bonus_activation`, `free_production_use`, `agency_supply_used_turn` and eleven others
store the value of the matching monotonic counter on `GameState`. The oracle's docstrings
explain why at length: a combat or tactical action can end down several paths — one side
wiped out, a retreat — and a flag leaks out of every path that does not clear it. A sequence
number lapses on its own. All four counters (`combat_round_seq`, `production_seq`,
`activation_seq`, `turn_seq`) are carried across, and `turn_seq` is exercised by
`each_turn_advances_the_turn_sequence`.

**Equality ignores the uncompared fields.** The oracle marks 20 `GameState` maps, 3 `Player`
maps, and 2 `SystemState` maps `compare=False`. That is reproduced field by field in manual
`PartialEq` impls. It means **`board` is excluded from equality** — two states differing only
in unit positions compare equal. That is surprising and it is what `tools/trace_equality.py`
depends on, so it is reproduced rather than quietly improved, with
`GameState::identical()` added for a full structural comparison and
`equality_ignores_the_fields_the_oracle_marks_uncompared` pinning both.

### Rules behaviour

| Behaviour | Test |
|---|---|
| A player holding two cards acts on the lower-numbered one (LRR 83.3) | `a_seat_holding_two_cards_acts_on_the_lower_one` |
| A cardless player has *not* exhausted their strategy card — a vacuous `all()` would let them pass | `a_cardless_player_has_not_exhausted_their_strategy_card` |
| Each held card exhausts separately | `each_held_card_exhausts_separately` |
| Swapping preserves the rest of the holding — assigning the whole holding would destroy a card in a three-player game | `swapping_a_card_preserves_the_rest_of_the_holding` |
| An exhausted card handed over arrives exhausted | `an_exhausted_card_handed_over_arrives_exhausted` |
| Dropping a holding does not leave a card exhausted behind | `dropping_a_holding_does_not_leave_a_card_exhausted_behind` |
| Two cards each snakes, so the speaker picks first and last | `two_cards_each_snakes_so_the_speaker_picks_first_and_last` |
| The picker is indexed by cards dealt, not by who is short of quota | `the_picker_is_indexed_by_cards_dealt_not_by_who_is_short` |
| There are always exactly eight strategy cards — the sets replace, they do not union | `there_are_always_exactly_eight_strategy_cards` |
| Turn order follows initiative, not seating | `the_turn_follows_initiative_order_not_seating_order` |
| A card left on the mat gains a trade good, after the draft (LRR 83.4) | `a_card_left_on_the_mat_gains_a_trade_good` |
| No agenda phase until the custodians token is lifted, then every round (LRR 8.1, 27.4) | `there_is_no_agenda_phase_until_the_custodians_token_is_lifted` |
| Removing a unit removes one, not every copy — units are values, not entities | `removing_a_unit_removes_one_of_it_not_every_copy` |
| A view hides other hands but keeps their size visible | `hand_size_stays_visible` |
| The leak check catches an unredacted state | `the_leak_check_actually_catches_a_leak` |

The eight-card assertion is worth naming: Construction exists three times in the corpus as
`base4`, `pok4construction`, and `te4construction`. Taking every card the sources allow
yields twelve cards and a duplicated initiative order. The corpus records the real sets in
`strategy_card_sets`, so the choice is read rather than reconstructed — the oracle notes
this was invisible while the default was base-only, where the union happens to be a valid
set.

### Differences from the oracle

| Difference | Reason |
|---|---|
| State is an owned value with `&mut self` mutators and `Clone`, not a frozen dataclass rebuilt by `replace()`. | A caller that needs the old state keeps a clone. Same guarantee, without rebuilding the whole structure on every field write. |
| `promises` serialises as a list of records, not a map. | JSON object keys must be strings and a promise is keyed by a triple. Flattening the key would need an escaping scheme that could collide with a promise whose text contains the separator. `BTreeMap` iteration is sorted, so the encoding stays canonical. |
| `controlled_planets` is not memoised. | The oracle caches it against Python cost (70,885 inner iterations per round-4 six-player game). Here it is a `BTreeMap` walk, and a cache on a mutable value is exactly the thing that goes stale. |
| `BTreeMap`/`BTreeSet` throughout, where the oracle uses `dict`/`frozenset`. | Determinism must not depend on map iteration order. Nothing in the oracle relies on `dict` insertion order for these fields; the two places that care sort explicitly. |
| `advance_phase` returns a `PhaseOutcome`. | So a caller can see that it reached the status phase rather than silently getting a phase flag flipped past unimplemented rules. |
| `spend_token` refuses to go negative. | The old `tactical.rs` decremented unchecked. Running out of command tokens is a real constraint that shapes the whole action phase. |
| `BotView` and `TtsView` are gone, not replaced. | They were invented, leaked, and had no oracle counterpart. A bot gets a redacted `GameState`, which is what `views.view_for` produces. |

## What is deliberately absent

`advance_phase` documents its own holes rather than papering over them:

* end of strategy phase — Imperial Arbiter's card swap (which must precede reading
  initiative order, because the swap is what changes it) and the technology hooks;
* end of action phase — the whole status phase (LRR 81): scoring, objective reveal, command
  token gain, repair, readying;
* end of status phase — the agenda phase (LRR 8).

Also absent: Fleet Logistics in `advance_turn` (when added it must return early *before* the
transaction reset, since the two actions are explicitly the same turn), movement, combat,
production, and legality checking.

## Open findings

1. **No independent review.** Waived by the project owner for the remaining work.
2. **No differential fixture evidence.** Still blocked on the missing oracle exporter. Every
   claim above is checked against the oracle's source and its own test file, not against an
   exported trace.
3. **`Galaxy` is still not wired into the engine.** `ti4-content::galaxy` exists and
   `GameState` has a board, but nothing connects them. Adjacency is available and unused
   until movement is written.
4. **`ti4-model::factions.rs` still carries the invented `FactionRecord`.** Its fleet parser
   is real and tested, but the record type duplicates what `ti4-content` now reads. Folding
   it in belongs in its own package.
5. **The status and agenda phases are stubs at the `PhaseOutcome` boundary.** A caller
   driving a full round will reach `StatusBegan` and find nothing happens.
