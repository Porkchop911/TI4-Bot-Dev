## Decisions made and rationale

- **A shared `choice::Capturing` decider, not a fourth local copy.** This package needed a
  context-capturing decider in five different files; `invasion.rs` and `strategy_cards.rs` each
  already wrote their own small local version in earlier `OBS-003` packages. Promoting one to
  `choice.rs`, alongside the already-shared `Scripted`/`FirstOption`/`AlwaysDecline`, avoided a
  fourth near-identical copy. The two earlier local copies were **not** retrofitted to use it: that
  would be unrelated cleanup riding on a typed-context package, and both already-committed packages
  are correct as they stand.
- **The new decider moved one registry baseline.** `Capturing::choose`'s own body calls
  `self.inner.choose(choice)`, which `decision_delivery_inventory.rs`'s scanner correctly counts as
  a new `choice.rs::choose` site (2 → 3). Updated the registry's expected baseline rather than
  treating the scanner's catch as noise — this is exactly the kind of drift the registry exists to
  catch, and the fix is confirming what changed, not suppressing the check.
- **`score_objective`, corrected from an initial `score_public_objective`.** Read the surrounding
  code before committing to a name (Representation rule: state facts, not authored labels) and found
  `next_askable` extends the public list with secret candidates for status timing specifically —
  the option list is genuinely mixed, and the non-status path is the only one that is ever
  secret-only.
- **Psychoarchaeology and Transit Diodes are not given bespoke fixtures.** Both are proven correct
  by the same `.contextualized` construction already exercised for Chaos Mapping/Bio-Stims in this
  slice, and the file's existing test suite (unmodified, still passing) exercises both functions
  end to end. A bespoke specialty-planet or ground-force-redeployment fixture for each would add
  test surface without adding coverage a reviewer could not already infer from the diff.
