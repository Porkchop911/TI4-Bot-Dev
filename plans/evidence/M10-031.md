## Design points worth stating

**Forced choices are dropped, and not as an optimisation.** A decision with one legal option has
teacher probability 1.0 whatever the teacher believes, so its KL term is identically zero. Keeping
them would add 55,997 records of pure weight — and they are not spread evenly across heads, so they
would tilt the per-faction mean toward whichever head is most often forced.

**Capture runs inside `choose_seeing`, from the engine-bound `SeatObservation`.** §6.1 requires that
capture "is built only from the acting seat's authorized view; it does not retain a raw omniscient
state as a shortcut". That holds by the types M09-021 and M09-027 established rather than by this
module's care: `critic_vector` takes the capability and has no other seat argument.

**The split is by seed and checked, not assumed.** `clusters_are_disjoint` computes the actual
intersection rather than trusting two constants to stay apart, because a constant is exactly the
thing a later edit widens by one. `read_shard` additionally rejects any record whose seed is not in
the cluster its shard claims — the leak the split exists to prevent, which nothing else would catch
since such a record is otherwise perfectly well formed.

**Streamed, not buffered.** At 1.08 M decisions each carrying every option's feature vector, holding
the corpus in memory before writing would need several GB. Shards are written straight into a zstd
encoder. That is sound only because **the capture's iteration order already is the required
deterministic order** — seeds ascending, then rotation, then seat, then decision index — and the
ordering is re-checked on read rather than assumed.

**Manifest written last**, so a directory without one is incomplete by construction: the same rule
the vocabulary generations and the schema-6 bundle already use.

## Plumbing added

- `LearnedBot::recording_critic(CriticFeatures)` and `critic_vectors()` — the option-free critic
  vector per decision, kept beside the trajectory rather than inside `TrajectoryStep`, which is a
  serialized type the linear trainer already consumes. Both buffers are pushed under the same
  `recording` branch, so index `i` in one is index `i` in the other.
- `rollout::play_capturing` — a recording rollout that returns the critic vectors alongside.
