**Raw path is structurally blind.** The raw dispatcher receives only `choice` and `option`; it
never sees state. Grep proof — zero private-field access in the policy scoring layer:

```text
$ grep -n "action_cards\|secret_objectives" crates/ti4-policy/src/bot.rs \
      crates/ti4-policy/src/scoring.rs crates/ti4-policy/src/valuation.rs

```

Objective points come from the static content corpus (`score_objective` reads `ContentStore`, not
state); casualty values from the unit price table. The raw bot cannot leak what it never holds.

**Seen path stays inside the typed seam.** Every position-sensitive scorer takes `&Observed`; all
calls observed in the seen scorers are within its public-facts API (`system`, `active_system`,
`can_reach`, `controlled_planets`, `available_spend`, `systems_with_units_of`,
`systems_with_token`, `seat → PublicSeat` (counts only), `players`, strategy-card facts,
`scored_by`, `units_held`, `scoreable_public/secret`). No method on `Observed` exposes another
player's card or secret identities; the counts-only seat is pinned by
`a_seat_is_seen_as_counts_never_as_identities`.

**Known limitations carried (from `plans/KNOWN_DIFFERENCES.md`):** ML-1 — `leaks()` is a two-field
hand-written mirror, not field-complete (M06's `event_feats` is the proof case where it did not
fire; no actual leak today because that field holds table-public ids). KD-4 — promissory-note
holdings are visible in redacted views (named gap since M08-001, pinned by a naming test). Both
remain open and unchanged by this gate.

## Part 2 — Parameter leakage (high): PASS

- **`Components`** is a named-parts vector; `total()` sums parts in construction order;
  `explain()` prints every part with its value. Aggregation is deterministic and explainable by
  construction — there is no hidden accumulator to drift.
- **`Decision`** keeps the per-option breakdown *and* the considered shortlist separately, so an
  explanation cannot hide the filter that did the work (doc comment at the field).
- **`ScoredBot` field audit — every field is read by a live path:**

```text
$ for f in rng content sources temperature decisions remember; do grep -c "self\.$f" bot.rs; done
rng: 1        (sample)
content: 5    (score_objective, score_casualty, valuation calls)
sources: 8    (source filters across scorers)
temperature: 2 (sample, at_temperature)
decisions: 1  (remembering log push)
remember: 2   (choose_from_scores gate, remembering builder)
```

  No dead knobs. The oracle's failure mode — identifier-shaped dictionary keys silently becoming
  tunable weights that no scorer read (`progress.rs` module doc) — is structurally impossible in
  this shape: `Progress` lives outside the bot class, and every field on `ScoredBot` has a reader.
