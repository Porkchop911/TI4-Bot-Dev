## Implementation

- `tools/generate_bounded_legacy_corpus.py` holds all source-produced traces in memory, verifies `replay_records` recreates each canonical byte stream, validates size limits, then atomically writes individual fixture files and the deterministic JSON manifest under the Rust repository.
- The retained files total **12,234,839 NDJSON bytes** (12,259,879 bytes including manifest), below the 20 MiB cap. Every trace is below 512 KiB.
- The bounded choice/event projection now canonicalizes `engine.dice.Roll` payloads, which occurs in `save54_te`; otherwise a valid bounded capture was refused rather than serialized.
- `validate_bounded_fixture_corpus` requires the pinned oracle commit, corpus schema, 100 unique IDs and paths, bounded sizes, SHA-256 matches, valid bounded trace headers, and resolved paths beneath the canonical fixture root. It refuses a symlink escape and non-normal relative paths.

## Tests and compatibility evidence

1. The exporter projection unit test covers an event payload containing a dice `Roll`.

3. Rust validates the committed corpus's count, size, checksums, parser validity, and header/manifest agreement.
4. Rust unit coverage rejects non-normal relative trace paths before filesystem access.

## Known difference and next boundary

The corpus has explicit selected option IDs and dice-roll entropy, but not enough native generic game behavior to prove equivalent Rust final-state/event projections. M03-007c remains blocked on that existing parity gap; no fixture is presented as a native replay success.
