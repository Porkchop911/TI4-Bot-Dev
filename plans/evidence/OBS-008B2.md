## Result

1. **`Quantity::Hits`.** OBS-007c's `hit_count_preview` was built with no consumer: "no producer
   attaches this yet — that is OBS-008b's job." This slice is that job. `Hits` names the count a
   roll (or one die) produces before any casualty is assigned; what the count implies downstream
   remains producer-specific, exactly as the helper's own doctrine states.
2. **Engine.** `choose_reroll_dice` now computes each die's current hit status from its face plus
   whatever per-die adjustment (Thalnos's +1) still sits on that position — the same arithmetic
   `RerollEntry::hits` already sums over a whole entry, applied per-die. The reroll option carries
   `unit`/`face`/`hits_on` payload and `stochastic::hit_count_preview(1, hits_on, …)`: a `Chanced`
   preview whose two cases (0 hits, 1 hit) carry `Hits` deltas from the current status to each
   redraw outcome. This is exact because a fresh d10 draw replaces both the face and its
   adjustment (`RerollEntry::deltas`'s own doc: "the adjustment dies with the die"), so the
   post-redraw distribution is precisely the uniform, unmodified threshold roll the helper models.
   The decline option carries the same `unit` payload and a `Preview::certain` fact that the die's
   status is unchanged. Both are omitted when `hits_on` is `None` — no threshold, no claim.
3. **Policy.** `combat_decision_features`, guarded on subtype `reroll_die`, mirrors the tactical
   surface for `Certain` outcomes (before/after/change) and adds a new read for `Chanced`
   outcomes: `Preview::expected(Quantity::Hits)` as `combat:hits-expected`, an exact rational
   rather than the whole per-case breakdown — deliberately bounded scope for this slice.
4. **New family.** `combat` is a genuinely new decision-surface family (unlike `load_cargo`/
   `commit_ground_forces`, which reused `tactical`): `EXPLICIT_FIXED_FAMILIES` (37 → 38),
   `projection::FAMILY_ROLES` (44 → 45, `Transferable`), and `OOV_REGISTRY_VERSION` 7 → 8
   (`OOV_FAMILIES_V8` appends `combat` at index 44; every earlier reserved column keeps its
   index). New pinned fingerprint
   `58abcdcf1c0e2fa21f6f8b97b6c9d233e489f92d7db57009e2fb11d8272bff59`. The one-version-back
   inference window moves to v7; v6 is now refused exactly as v2-v5.

## Focused evidence

- `combat.rs::obs008b2_reroll_options_preview_the_dies_exact_hit_distribution`: a dreadnought die
  showing 5, hitting on 6+ (a current miss). The reroll option names `unit: "dreadnought"`,
  `face: 5`, `hits_on: 6`, and previews `Chanced { out_of: 10 }` with a 5-weight `0-hits` case
  (`Hits: 0 -> 0`) and a 5-weight `1-hits` case (`Hits: 0 -> 1`); the decline option previews
  `Certain([Hits: 0 -> 0])`.
- `features.rs::obs008b2_reroll_options_carry_subtype_and_hit_expectation`: the same shape built
  directly as a `Choice`. `combat:subtype:reroll_die`, `combat:option-count` (2),
  `combat:preview-known`, and `combat:hits-expected` (exactly 0.5) reach the policy on the reroll
  option; the decline option carries `preview-known` but no `hits-expected` (a certain preview has
  no chanced expectation); a `Certain` preview (hitting on 1, always a hit) reads
  `combat:hits-after`/`combat:hits-change` instead; the expectation survives `mlp_option_features`
  and `projection::admits`.
