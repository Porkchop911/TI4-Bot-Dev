## Design decisions recorded in implementation

1. **Crossed emission is the delivery mechanism.** MLP §5.1's bare names
   (`objective-progress:<family>` etc.) are preserved verbatim as the fact-name portion of crossed
   names: `state-kind:<kind>:<fact>` under `StateCross::ByKind`, `state-option:<id>:<fact>` under
   `ByOption`, inert under `None`. Uncrossed emission would be mathematically inert in every linear
   softmax head (option-invariant features cancel in the logit sum), so this is an architectural
   reconciliation with the accepted StateCross design, not a deviation.
2. **Family tokens use underscores** (`cost_spend_resources`, `colours_2`,
   `planets_of_trait_cultural`): MLP §5.1's `cost-<kind>` hyphen is pseudocode; the accepted
   feature-name convention uses underscores within a token. Parameterised variants fold their
   parameter in, matching how the corpus distinguishes them.
3. **Max before vector construction.** Aggregation happens in `objective_facts()` over plain
   `(name, value)` pairs with explicit max per family and per (family, threshold); no duplicate
   names ever rely on the vector's additive merge (§5.1 aggregation rule).
4. **Zero-skip convention preserved**: zero-valued progress facts are dropped (the vector already
   encodes absence as zero), but `objective-need:<family>:<threshold>` markers and count/stage
   slots are always emitted — a ratio alone cannot distinguish "3 of 4" from "9 of 12".
5. **Occurrence-based secrets emit nothing**: they have no position-progress representation; the
   accessor skips them rather than zero-filling (same convention as missing galaxy context).

## F-M09-021-1 round 2 — typed private-view boundary (implementer, 2026-08-24)

The recheck's diagnosis was accepted in full: `Choice` is public and freely constructible, so
deriving the acting seat from it authenticated nothing. The correction replaces caller convention
with a type-level binding. Design and writable-path declarations (made before editing) are in
`plans/M09-021_OPEN_REVIEW_ITEMS.md`, section "F-M09-021-1 round 2".

### What changed

1. **New public type `SeatObservation<'a>`** (`crates/ti4-engine/src/choice.rs`). Private fields,
   **no public constructor**; the only values that exist are produced by engine ask paths
   (`Table::ask_seeing` and its window sibling), where the decider was just looked up by
   `choice.player`. Methods: `observed()`, `bound_seat()` (named to avoid shadowing the deref'd
   public accessor `Observed::seat(player)`), argumentless `held_secret_progress()`, and
   argumentless `held_state()`. Deref's to `Observed` so every public-fact call site is unchanged.
2. **`Observed::held_secret_progress_for_choice` removed.** No method on `Observed` returns named
   secret data with any caller-controlled identity argument — the criterion holds by type surface,
   not convention.
3. **`Decider::choose_seeing` now takes `&SeatObservation<'_>`** (was `&Observed<'_>`). Live play:
   engine ask → bound capability → decider → `LearnedBot::consider(seen.observed(), choice, &seen.held_secret_progress())`.
4. **Explicit-records API for offline contexts.** `explicit_choice_features` /
   `explicit_option_features` take `held_secrets: &[CardProgress]`; a documented free function
   `ti4_engine::choice::held_secret_progress(state, content, sources, galaxy, viewer)` computes the
   records from full state (offline/training/diagnostic contexts hold it by design). Every call
   site names the secret data its extraction uses.
5. **`ask_private(choice, seen, decider)`** — public test/offline seam that performs the identical
   engine binding internally and validates through the shared `validate`; the capability never
   escapes to caller code.
6. **Redaction boundary closed in the same round (discovered during implementation).**
   `Observed::redacted_for(viewer)` had the identical hole: a public method taking an arbitrary
   viewer, returning that viewer's unredacted secret cards — reachable from live decision code via
   deref. It is removed; its logic now lives in `SeatObservation::held_state()` (no arguments, bound
   seat only) plus a private `redact_others` helper. The three training examples that called it
   with their own seat (`military_support`, `objective_report`, `vp_where`) switch to
   `seen.held_state()`. This extension was declared in the ledger addendum after discovery, before
   those edits; flagged for reviewer confirmation.
7. **Incidental cleanup (declared):** one dangling doc line + `#[must_use]` between methods in
   `choice.rs` (left by an earlier refactor of `scored_by`; caused a pre-existing
   "unused attribute" warning) moved to where it belongs, on `scored_by`.
