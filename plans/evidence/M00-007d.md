## Event projection (from engine/timing.py)

### Event
```python
@dataclass
class Event:
    """A typed occurrence that abilities may trigger on.
    
    payload is deliberately mutable: WHEN abilities modify the event before it
    resolves (LRR 1.15). cancelled suppresses both the event's own resolution
    and its AFTER window.
    """
    event_type: str
    payload: dict
    cancelled: bool
    _id: int  # unique ID for replay
```

### Relation
```python
class Relation(Enum):
    WHEN = "when"      # resolves before the event; may modify/cancel it
    AFTER = "after"    # resolves once the event has happened
```

### Frequency

```python
class Frequency(Enum):
```

### Phase

```python
class Phase(Enum):

```

### Resolution rules (LRR anchors)
- LRR 1.6: "cannot" effects are absolute
- LRR 1.15: "when" abilities may modify or replace the event they trigger on
- LRR 1.16: "when" resolves before "after" for the same event
- LRR 1.18: an ability resolves once per occurrence of its trigger
- LRR 1.19: in action phase, players take turns resolving in initiative order
- LRR 1.20: in strategy and agenda phases, order is clockwise from speaker
- Windows are round-robin; passing gives another opportunity on new events
- Abilities that emit events during resolution nest depth-first
