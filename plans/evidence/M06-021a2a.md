## Finding

`CombatWindow::settle` currently rolls anti-fighter barrage and ordinary combat
dice in one automatic transition. `AftermathWindow::settle` treats a combat with
no pending player choice as complete and advances to invasion/production. A
correct AFB pause therefore requires one coherent state-machine change: the
combat window must expose a resumable occurrence boundary, and the game driver
must retain the aftermath window while `event_scoring` resolves it. Implementing
only the feat emitter or only an occurrence accessor would either delay the
window until after ordinary dice or incorrectly advance the tactical action.

The initial focused red test compiled as expected only after the absent
`CombatWindow::take_scoring_occurrence` API was implemented. The final design retains
the aftermath window across each scoring pause and resumes the exact automatic stage.

## Implementation

1. `CombatWindow` represents an AFB scoring pause and resumes into the exact
   pre-combat-dice stage.
2. `AftermathWindow` surfaces pending occurrences without advancing stage.
3. `Game` opens `ScoringWindow::for_occurrence` and, when it closes, resumes
   that retained aftermath window.
4. Space cannon uses a separate `AnyPerPlayer` non-combat occurrence. Barrage and
   completed space combat share one `OnePerPlayer` combat occurrence; the persistent
   `(player, occurrence)` score ledger prevents a second score across the two pauses.
