## Affinity and worker policy

### CPU affinity
- Single-core benchmarks: Pin to core 0 (isolate from OS scheduling).
- Multi-core benchmarks: Pin workers to distinct cores (no hyperthreading sharing).
- Use `SetThreadAffinityMask` on Windows.

### Worker counts
| Benchmark | Worker count | Rationale |
|---|---|---|
| Single-core game | 1 | Per master plan metric |
| Fixed-worker throughput | 12 | Per master plan (12 workers) |
| Policy scoring | 1 | Per master plan metric |
| Snapshot/fork | 1 | Per master plan metric |
| Stage 2 training | GPU count (typically 1) | Per master plan metric |
| Peak memory | 1 | Per worker measurement |

### Threading policy
- Python reference: Use GIL-aware threading (one worker per core max).
- Rust: Use rayon or crossbeam for parallelism; pin to cores.
- No background processes during measurement (close IDE, browser, etc.).

### Environment isolation
- Disable Windows power saving during measurement.
- Set power plan to "High Performance".
- Close all non-essential applications.
- Run at consistent time of day (or randomize and control for time).
