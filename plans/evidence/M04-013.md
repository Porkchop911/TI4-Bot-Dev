## Implemented behavior

- `Game::with_seeded_random(state, content, seed)` creates a `Table` whose default decider is the
  existing `SeededRandom` and therefore answers every unseated player from one shared stream.
- The stream advances by global decision order, matching the oracle's
  `Table(default=SeededRandom(seed))` model. It deliberately does not create one same-seed stream
  per player, which would change the decision sequence.
- Every answer still passes through `Table::ask` and generated-choice validation before it can be
  recorded or applied. The random driver therefore cannot fabricate an action.
- Same seed produces the same event/decision trace; distinct pinned seeds produce different legal
  traces. A bounded random run reaches the explicit M04-012 status-choice boundary rather than
  deadlocking or being reported as a completed game.

## Compatibility and review

This preserves the oracle's semantic table shape—one seeded random default used by every player—
and verifies the legal-choice boundary plus repeatable native traces. It is not byte-for-byte
oracle-seed parity: the existing Rust `SeededRandom` intentionally uses ChaCha8 instead of Python's
Mersenne Twister; exact oracle replay remains decision-log based. There is no differential exporter
yet (M00-009 remains open), so no parity claim or benchmark claim is made.
