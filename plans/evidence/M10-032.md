## What phase 0 does

Six schema-4 linear champions become one shared MLP trunk with shared + per-faction residual
readouts, by minimising KL against the captured teacher distributions. Supervised only, no reward.

```
minimise  mean over six factions of ( mean over that faction's decisions of KL(teacher ‖ student) )
```

**The mean of means is not a stylistic choice.** The corpus is lopsided by construction — hacan
contributes 170,852 training decisions to letnev's 115,429, because hacan's games run longer. A
pooled mean would hand hacan 21% of the shared trunk's gradient and letnev 14% for that reason
alone. The per-batch weights are computed from each batch's own composition, so a batch that happens
to draw more hacan decisions does not thereby weight hacan more.

**Student temperature is fixed at 1.0.** Teacher probabilities already contain each teacher
checkpoint's temperature; a learned student temperature would be an unidentifiable second logit
scale, since any temperature can be absorbed into the readout weights.

## Initialisation

§6.1's, from a pinned ChaCha8 stream seeded 20,260,821 — not a libtorch initialiser, so the starting
weights are a property of the plan rather than of the linked build:

| tensor | initialisation |
|---|---|
| active input rows | `U(±sqrt(6/32))` |
| hidden | `U(±sqrt(6/width))` |
| shared readout | `U(±1/sqrt(width))` |
| every bias, value head, critic rows, faction residuals, identity embeddings | **zero** |

Rows no feature can reach stay zero, so the model carries no parameters nothing can train. Faction
residuals starting at zero mean the student begins as the shared model and earns any per-faction
deviation.

## Optimiser

Adam, hand-rolled: `lr 3e-4, betas (0.9, 0.999), eps 1e-8, weight_decay 1e-5`, batch 4,096, global
gradient-norm clip 1.0, at most 20 epochs, patience 3, ties within 1e-5 to the earlier epoch.

Hand-rolled because the actor holds its tensors directly so a bundle can name each one, and because
M10-035's resume has to serialise the moments regardless. The clip is on the **global** norm across
every parameter: clipping each tensor separately would change the update's direction, not only its
length.

Untrained faction rows are re-zeroed after every step rather than trusted to receive no gradient —
weight decay acts on a parameter whether or not it got one.

## The speed-up, and how it was found

The first epoch took **865.9 s**. The measurement that explains it:

```
forward, per decision              63 us
forward + backward, per decision  1494 us
input gradient shape        [16384, 256]
```

The backward is 24× the forward because `index_select`'s backward scatters into a **dense
`[capacity, width]` gradient — 16.8 MB — once per decision**, however few of its rows that decision
actually touched. Grouping decisions that share a `(faction, head)` pair into one forward pays that
once per group instead: the same measurement grouped is **501 us**, and an epoch is **135.9 s — 6.4×**.
The 20-epoch run drops from about 4.5 hours to about 22 minutes.

Two things worth recording against a future reader:

- The grouped **forward** is *slower* — 288 us against 63 — because the batched gather materialises
  a larger intermediate. Optimising on forward timings alone would remove this change.
- `gather_reduce_batch` now picks its combination strategy by size. The dense `[options, distinct]`
  weight matrix is right at inference scale (6.2 options × 131.9 distinct rows) and becomes 34
  million floats for a training micro-batch, which measured at **0.11× — slower than not batching at
  all**. Above the threshold it uses a segment sum.

This was found by building `examples/batch_probe.rs` after guessing wrong. That is the second time in
this milestone: M09-029's three optimisation attempts included one that made things slower.

**Equivalence check.** The grouped implementation reproduces the ungrouped run: train KL identical at
0.10853, validation KL 0.03229 against 0.03228 — the f32 reassociation grouping implies.

## Non-vacuity

`Distillation::parameter_movement` reports the L2 distance from initialisation and the driver
**refuses a run reporting zero**. `Adam::step` skips any parameter whose gradient is undefined, so a
break anywhere between the loss and the leaf tensors would otherwise produce a complete and entirely
plausible table of KLs it never trained toward.

### The exit gates §6.1 declares

| gate | required | measured | |
|---|---|---|---|
| mean KL | ≤ 0.02 nats | **0.00138** | ✓ 14× under |
| worst head KL | ≤ 0.05 | 0.017 | ✓ |
| gameplay mean VP vs r6 | within 0.1 | **0.0129** | ✓ 8× under |
| top-1 agreement | ≥ 97% | 93.730% | **waived, D-2026-08-26-1** |

The gameplay gate is the one that carries the weight: 200 seeds × six rotations, paired on identical
games, and the student finishes **0.0129 VP** from the r6 champions. The architecture has reproduced
the teacher *in play*, which is what §6.1's failure clause is about — so `DAgger not required: the
base pass cleared both exit gates`.

### The waiver, and what the run says about it

**Operator decision D-2026-08-26-1** waives top-1 agreement. §6.1 requires ≥ 97%; the run measured
93.730% at a mean KL of 0.00138 nats. At that KL the two distributions are all but identical, so the
disagreements are argmax flips on options the teacher holds near-tied — which fitting harder cannot
remove, and which DAgger does not address, since DAgger corrects distribution drift rather than
tie-breaking. The operator's ground is that PPO deliberately diverges from the teacher from here.

The gameplay result is independent evidence that the waiver was not papering over a defect: a student
disagreeing on 6.3% of argmaxes still plays to within 0.013 VP of the teachers. The number is still
computed and printed every run, so a later reader sees exactly what was set aside.

### An earlier run of this row was void

The first distillation reported validation KL 0.00642 and is discarded. It trained on a corpus that
captured the **raw** schema-4 features rather than the projected vectors the MLP consumes — 131,353
`prompt-option` and 40,339 `state-option` features present per 2,000 decisions that the projection
suppresses, and none of the `seat-state` facts it adds. See M10-031's evidence and `a21e1ff`.

Nothing about that run looked wrong: records well formed, checksums matching, KL falling smoothly
across twenty epochs. It surfaced only because a zero-drop check refused a feature that was not in
the accepted vocabulary.
