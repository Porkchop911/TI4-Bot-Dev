# M00-009j — Bounded-game scripted replay

## Package specification

- **Milestone/package:** M00-009j, prerequisite split for M00-010; dependency M00-009i
  (`dca1feb`).
- **Objective:** Reconstruct a bounded seeded oracle scenario from its captured legal option IDs
  and prove its canonical NDJSON bytes equal the original trace.
- **Oracle sources/tests inspected read-only:** `engine/choice.py`, `engine/dice.py`, `engine/game.py`,
  and `engine/timing.py`, plus replay coverage in `tests/test_combat.py`, at
  `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 oracle inspection; P1 writes limited to `tools/oracle_exporter/`,
  `tools/oracle_replay.py`, the focused exporter test, this evidence file, and
  `plans/EXECUTION_STATE.md`. No network or oracle writes.
- **Inputs/outputs:** bounded-game NDJSON records with a header and selected choice IDs in; a
  canonical replay record list or atomically written NDJSON file out.
- **Compatibility class:** exact bytes for supported bounded scenarios. The original trace header
  is reused semantically through its scenario/seed/round count; selected IDs remain oracle-legal
  because replay uses `Scripted` through `Table` validation.
- **Explicit non-goals:** replaying unbounded games, generating the M00-010 corpus, hiding invalid
  scripts, or claiming Rust parity.

## Implementation

- `bounded_game_records` now accepts an optional script; absent script keeps seeded random legal
  choices, while replay feeds its captured selection sequence to the oracle `Scripted` decider.
- Added canonical byte encoding and `replay_records`, which rejects a missing/non-bounded header.
- Added `tools/oracle_replay.py`; it reads NDJSON, replays it, and atomically writes only to a path
  contained by this repository.
- Event UIDs are process-global in the oracle. The bounded runner resets that in-memory iterator to
  one before each run so prior exports in the same Python process cannot change recorded bytes.
  No oracle file is modified.

## Compatibility and review

Resetting the process-global UID iterator is necessary trace isolation, not a gameplay change: every
independent fresh Python oracle process starts it at one. The runner remains single-process and
single-game; concurrent exports are explicitly out of scope. Independent review is owner-waived;
no reviewer is claimed.
