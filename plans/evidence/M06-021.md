## Protocol deviations

This package did not follow the `AGENTS.md` package loop. Recorded here rather
than quietly corrected, because the loop exists to catch exactly the kind of
error a self-reviewed package cannot catch.

1. **No package specification before implementation.** The work was scoped from a
   conversation, not from a task specification in the
   `PI_WORK_PACKAGE_STANDARD.md` template.
2. **No scoped permission declaration.** The 150-game measurement runs are P2
   (bounded simulation output) and were run undeclared. They wrote only to
   `target/` and read only from `out/`; no external state was touched.
3. **The Python oracle was not inspected.** The twelve event-conditioned secrets
   have no requirement in the oracle either, so there was nothing to port — but
   that was assumed rather than checked, and a reviewer should verify it.
4. **No independent review.** Tier C requires a frontier review that is not the
   implementer. Outstanding, and it **blocks M06-022**.
5. **Evidence filed under `docs/evidence/`** rather than `plans/evidence/`.
   Corrected by moving this file.

## Objective

Make scoreable the fourteen secret objectives that no sequence of play could
score: twelve with no registered requirement, and two (`dp`, `dtd`) whose
requirement existed but which nothing ever offered, because `scoreable_on`
returns status-timed secrets only.

## Changed paths

```
crates/ti4-model/src/state.rs        Feat enum, Player::feats, record_feat/did_at_turn
crates/ti4-engine/src/combat.rs      before_combat, note_combat_feats, AFB feat
crates/ti4-engine/src/invasion.rs    bombardment feat
crates/ti4-engine/src/game.rs        event window, pass feat, agenda election feat
crates/ti4-engine/src/secrets.rs     feat_for, scoreable_event, bam requirement
crates/ti4-engine/src/objectives.rs  ScoringWindow::for_event
```

Six files — above the standard's one-to-five guidance. A reviewer should judge
whether the model change (`state.rs`) ought to have been a separate package;
the argument for keeping it together is that the ledger has no meaning and no
test without a consumer.

## Invariants

- Status-timed secrets are never offered in an event window, and event-timed
  secrets are never offered in the 81.1 window. Both directions tested; either
  leak would score a card twice.
- A feat satisfies only the turn it was recorded in, so a combat won in round 1
  cannot pay out in round 4.
- Opponents' held secrets remain unreadable — this package adds no feature and
  no observation path.
- Combat resolution itself is unchanged; every write is additive.

## Benchmark effect

Not measured. The event window opens only when a feat was recorded in the turn,
guarded by `anyone_did_at_turn`, so the common path is one vector scan per turn.
A reviewer may reasonably require a measurement rather than this argument.

## Unresolved

- Tier C review outstanding (deviation 4). **Blocks M06-022.**
- Six of the fourteen still score 0% over 150 games — flagship destruction,
  combat in an anomaly or a rival home, losing a home planet. Believed to be
  genuine rarity inside a four-round horizon rather than a defect, but that is
  an inference from the mechanism, not a measurement. A longer-horizon run
  would settle it.
- `Become a Martyr` is implemented as a position (a home planet in another
  player's hands) rather than as an event. Defensible, and a reviewer should
  confirm the reading.
- The event window is offered once per turn, which approximates 61.6's
  one-objective-per-action but is not identical for a turn containing several
  combats.
