## Implementation

### `PanelMetrics` / `FactionMetrics`
Per-faction metrics from a panel of games, mirroring the oracle's `metrics()` output:
- `stalled`, `clearance`, `shortfall`, `planets`, `systems`, `units`, `victory_points`, `vp_margin`, `won_or_tied`

### `PromotionConfig`
Threshold parameters for promotion decisions:
- `shortfall_margin`: minimum aggregate clearance gain (default 0.05)
- `max_faction_shortfall_regression`: per-faction shortfall allowance (default 0.03)
- `max_faction_clearance_regression`: per-faction clearance regression allowance (default 0.0)
- `epsilon`: floating-point comparison tolerance (default 1e-12)

### `Promotion` struct
Manages champion/learner separation:
- `acceptable_assembled()`: checks all three criteria from `acceptable_table()`
  1. Per-faction clearance veto
  2. Per-faction shortfall veto
  3. Aggregate clearance gain exceeds shortfall margin
- `is_better()`: Stage 1 comparison from `better()` — clearance first, shortfall tiebreak
- `promote()`: tries assembled path first, then isolated path
- `apply_promotion()`: updates champion profiles and metrics

### `PromotionResult`
Outcome of a promotion evaluation:
- `promoted`: list of promoted faction names
- `accepted_kind`: `Assembled`, `Isolated`, or `None`
- `candidate_metrics` / `champion_metrics`: the metrics that were evaluated

## Known limitations
- `learner_profiles` parameter in `promote()` is not yet used — it's reserved for the future integration with `train()` where the actual learner profiles will be passed.
- No confirmation panel support yet (oracle runs validation + confirmation panels separately; this implementation assumes the caller has already run both).
- No stall rate checking (oracle's `check_stalls()` is called before evaluation; this module assumes the input metrics are from a valid panel).
