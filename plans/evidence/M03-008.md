## Contract reconciliation

The old placeholder document declared a `HashMap`/`serde_json::Value` model complete although no
event module existed. The implementation instead uses `BTreeMap<String, Value>` so a payload has
stable wire order, an explicit trace-owned one-based ID sequence rather than the oracle's
process-global counter, mutable payload and cancellation state, lightweight type accessors, and
fallible generic typed decoding. A trace-owned sequence mirrors the exporter's explicit reset to
one while avoiding cross-test or cross-game ID drift.

## Result and compatibility evidence

`Event` preserves the oracle's mutable payload and cancellation semantics. Its JSON fields are
`id`, `event_type`, `payload`, and `cancelled`, matching the canonical exporter projection. The
oracle's module-global UID counter is intentionally translated to `EventSequence`, owned by a
game/trace; the exporter itself resets the Python global to one for each trace, so a trace-local
allocator preserves the observable behavior while removing cross-run nondeterminism.

`Event::decode` is the explicit boundary for future rules that need a typed ID or structured
value. Primitive reads intentionally follow the oracle's permissive lookup behavior: missing or
wrongly typed fields return `None`, not a coerced value.
