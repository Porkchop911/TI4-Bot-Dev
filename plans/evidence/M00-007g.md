## Ordering rules

### State ordering
- Players ordered by `initiative_order` (not player_ids)
- Systems ordered by `system.id` for deterministic output
- Units within a system ordered by `owner`, then `type_id`, then `sustained_damage`
- Command tokens ordered by player ID

### Event ordering
- Events ordered by `_id` (unique counter, starts at 1)
- WHEN abilities resolve before AFTER abilities for same event
- Within a window, ordering follows phase rules:
  - STRATEGY/AGENDA: clockwise from speaker
  - ACTION: initiative order from active player
- Abilities that emit events nest depth-first

### Choice ordering
- Options ordered by `first_of_each()` which preserves original order
- `distinct_units()` deduplicates by (type_id, sustained_damage), keeps first index
- DECLINE option always present as last option

### Redaction rules

#### Per-player views (engine/views.py)
```python
PRIVATE_SEQUENCES = ("action_cards", "secret_objectives")
HIDDEN = "?"
```

#### Redaction invariants
1. Viewer's own state is untouched (you know your own hand)
2. Board state is shared (public information)
3. Only other players' private holdings are redacted
4. Public counts survive; identities do not
5. `promissory_notes` is NOT redacted (public information)
6. `lrr 61.17` makes unscored secret objectives hidden until scored

#### Redacted view structure
```json
{
  "type": "view",
  "viewer": str,
  "players": [
    {
      "id": str,
      "action_cards_count": int,
      "action_cards": ["?", "?", ...],  // HIDDEN markers
      "secret_objectives_count": int,
      "secret_objectives": ["?", "?", ...],  // HIDDEN markers
      "promissory_notes_count": int,
      "promissory_notes": ["id1", "id2", ...]  // NOT redacted
    }
  ]
}
```
