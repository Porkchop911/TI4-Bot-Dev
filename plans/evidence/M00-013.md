## Bounded smoke result — not a baseline

The guard passed before execution. The oracle script was invoked from the Rust worktree with an
explicit result path under ignored `.tmp-m00-013/`, never its default `oracle/out/` path:

```text
python D:\Projects\ti4-engine\tools\benchmark_engine.py \
  --workers 1 --games 1 --seeds 1 --samples 1 --horizon 1 \
  --out D:\Projects\ti4-engine-rs\.tmp-m00-013\smoke.json
```

It completed in 3.1 seconds and reported a one-round game time of 0.185 seconds, 265 decisions,
14.2 ms fork mean, and 2.40 games/s. These values are diagnostic only: one sample has no variance
meaning and the workload is not the M00-012 protocol workload. Its one generated JSON file was
ignored by `.gitignore` and removed after recording this result. The post-run oracle status was
clean at the pinned commit.

## Blocker

M00-013 cannot produce an accepted performance baseline yet:

1. M00-012 requires ten warmups, thirty raw monotonic-clock samples per implementation, a host
   fingerprint, deterministic interleaving, and a variance decision. The oracle's
   `tools/benchmark_engine.py` emits one aggregate run using `time.time()` and no raw-sample or
   host schema.
2. The Rust comparison side does not exist: `crates/ti4-sim/src/benchmark.rs::Benchmark::run`
   is `todo!("M10: implement benchmarks")`.
3. The master plan prohibits a performance result without semantic parity for its workload.
   M00-010 has no approved generated corpus and the execution-state ledger records that no
   Rust/Python cross-engine comparison exists.

Writing a local wrapper would solve only item 1; it would still create an unpaired report that
cannot support the claimed gate. Filling the Rust benchmark or accepting an unpaired baseline
would broaden M00-013's established compatibility policy. No measurement is therefore accepted
or claimed.
