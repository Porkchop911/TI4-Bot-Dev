# M04-010 — Status phase

## Package specification

- **Milestone / dependencies:** M04; M04-006 and M04-007 complete.
- **Objective:** Resolve deterministic status bookkeeping—objective reveal, initiative-ordered
  action-card draws, command-token return, ready/repair, and strategy-card/pass reset—without
  pretending that choice-dependent scoring or command-token allocation is complete.
- **Python oracle:** `engine/game.py`: `_status_phase`, `_reveal_objective`, `_repair_units`,
  `gain_tokens`, and `_advance_phase`; `tests/test_game.py:test_status_phase_returns_strategy_cards_and_clears_passes`.
- **Oracle revision:** `37061c511a4780d4c0719e0342533a498cd4b457`
  (`codex/fully-learned-policy`), verified clean before implementation.
- **Permission class:** P1. Writable paths were `crates/ti4-engine/src/{status,phase,lib}.rs`,
  this evidence file, and `plans/EXECUTION_STATE.md`. No network, external process, artifact, or
  external-state effects.

## Implementation and compatibility

- `resolve_status_phase` only runs in `Phase::Status`; wrong-phase calls are rejected atomically.
- It reveals one public objective and marks the game finished when the objective deck is empty,
  matching the oracle's immediate objective-exhaustion end condition.
- It retains initiative order through action-card draws (including Neural Motivator `nm`'s second
  card), then removes command tokens from each board system, readies exhausted technologies and
  planets, repairs damaged space units, and finally returns every strategy card and clears passes.
- The report carries deterministic per-step outputs in BTree-backed board order and player/holding
  order, so the later event/step driver has the facts it must announce.
- Public/secret objective scoring and each player's two command-token allocation choices are
  explicit non-goals. They require generated choices and will be owned by M04-012; neither is
  replaced with an arbitrary default pool or automatic score.
- The resolver is intentionally not invoked by `advance_phase` yet: integrating its decision
  windows before a step owner exists would make incomplete gameplay look successful.
