## Which side the types are cut against

The M11 exit gate is that *the existing Lua executor communicates with Rust unchanged*. So
`tts/bridge_executor.lua` in the pinned historical repository is the contract, not `bridge/server.py`
— the Lua is the side that cannot be redeployed to every table already running the mod. Both were
read; where they differ the Lua wins.

Two consequences shaped the types and are easy to lose:

1. **An outcome is not JSON.** `bridgeResult` (executor line 282) appends a *line* —
   `result <id> <outcome>` with an optional `: <detail>` — and that log rides back inside the next
   poll body. So `Outcome::parse` reads a line, and `PollRequest` is where outcomes actually arrive.
   Modelling `Outcome` as a JSON envelope would have been wrong in a way no test would catch until
   M11-006 tried to match real logs.
2. **`id` is genuinely optional.** The executor reports nothing at all for a command without one
   (`if command.id then`), because a hand-queued command has nobody waiting on the answer. `action`
   is the opposite: the executor refuses a command whose action is not a string, so it is mandatory
   here and a command without one fails to parse.

## The three decisions worth reviewing

**A command carries its unmodelled fields.** `#[serde(flatten)] rest` rather than a per-action enum.
The builders that own per-action shapes are M11-014 and M11-015; until they exist, a command that
silently lost `from` would be executed as a *different move*. It also keeps `QueueResponse` honest —
the historical bridge returns the stamped command whole precisely so a caller echoing the result
cannot display one thing and have queued another, and that guarantee is worth nothing if the echo
passes through a lossy type.

**`CommandId` is `u64`, which is narrower than the historical bridge.** Python keeps any
caller-supplied `id` unchanged, including a float or a string. That cannot work: the executor
renders the id with Lua's `tostring` when it reports the outcome, so an id of `1.0` comes back as
`result 1.0 ok` and matches no command that was ever queued. An id that cannot survive the round
trip is not an id, so a non-integral one is refused at the boundary. This is a deliberate narrowing
against a historical behaviour, recorded here rather than left to be discovered in M11-004.

**Tolerance is asymmetric.** `PollRequest::lenient` never fails — an unreadable body becomes an
empty poll — because the poll is *also* how commands reach the table, and refusing one because an
older executor posted `{}` would strand a table with no way to be given orders. Fields are taken
individually for the same reason: a good `log` beside a malformed `turn` keeps its log. A malformed
`/queue` submission is the opposite case and is refused, because it comes from another process on
this machine and refusing it surfaces the mistake where it was made instead of in a game's chat.

## Never invent success

`Outcome::parse` distinguishes three failures and produces `Ok` from none of them:

| line | result |
|---|---|
| `polling every 2s` | `NotAResult` — ordinary output, the normal case |
| `result seven ok` | `UnreadableId("seven")` |
| `result 4 done` | `UnknownStatus("done")` |
| `result 4 OK` | `UnknownStatus("OK")` — the executor writes lower case |
| `result 4` | `UnknownStatus("")` |

The distinction between "not a result" and "a result I cannot read" is kept because the caller's
response differs: the first is expected and silent, the second is a contract break worth surfacing.
M11-006 owns matching outcomes to commands and deciding what silence means; this package only
guarantees that no unreadable line can be mistaken for a success.

A detail may itself contain colons — Lua's own error text does, as in
`attempt to index a nil value: field 'units'` — so the split is at the first colon after the status
and the remainder is kept whole. `Outcome::to_line` is the inverse, and the round trip is tested on
all three statuses.

## Golden corpus

`crates/ti4-bridge/tests/golden/` holds one file per envelope. Each is parsed, re-serialised, and
required to reproduce the same JSON *value* — not the same bytes, since the files are indented for
reading and the wire is not. Value equality is the property that matters: it proves nothing was
dropped and nothing invented, including fields this crate does not model.

`command.json` covers the eight actions `bridgeDispatch` routes (`ping`, `activate`, `move`, `land`,
`claim`, `control`, `card`, `token`) plus one deliberately unstamped command, so the id-optional path
is exercised rather than assumed. `poll.json` carries three result lines among two ordinary log
lines, so the outcome filter is tested against real noise rather than a corpus of pure results.

These files are checked in rather than generated: the historical bridge's own fixtures live in a
repository that is read-only and pinned at `37061c5`, and cannot be regenerated here.

## Scope not taken

- No transport, no bounded bodies, no loopback binding — M11-002.
- No queue policy, sequence numbers or restart semantics — M11-004. `QueueResponse` describes the
  answer; it does not decide what goes in it.
- No matching of outcomes to commands, and no decision about what silence means — M11-006.
- No per-action command validation — M11-014, M11-015.
- Python parity is not claimed and is not an acceptance criterion (`AGENTS.md`, 2026-08-21). The
  historical repository was read at its pinned commit and not written to.
