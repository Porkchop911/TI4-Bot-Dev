## Oracle exporter design

### CLI interface
```
python tools/oracle_export.py \
  --game-id <id> \
  --seed <int> \
  --seats sol=sol,letnev=letnev,xxcha=xxcha,hacan=hacan,jolnar=jolnar,l1z1x=l1z1x \
  --sources base,pok,thunders_edge \
  --output out/export_<id>.ndjson \
  --schema-version 1.0.0
```

### Module structure
```
tools/oracle_exporter/
  __init__.py          # Public API
  cli.py               # CLI entry point
  exporter.py          # Core exporter
  projections/
    state.py           # State projection (M00-007a)
    view.py            # View projection (M00-007b)
    choice.py          # Choice projection (M00-007c)
    event.py           # Event projection (M00-007d)
    outcome.py         # Outcome projection (M00-007e)
    error.py           # Error projection (M00-007f)
  schema.py            # Schema validation (M00-007h)
```

### Key design decisions
1. **Read-only oracle invocation**: The exporter imports from engine/ and bridge/ but never writes to them.
2. **NDJSON output**: One JSON object per line, following M00-007h schema.
3. **Deterministic seeding**: All random state is seeded explicitly for reproducibility.
4. **Projection hooks**: The exporter hooks into the game loop at:
   - State boundaries (phase transitions)
   - Choice boundaries (before/after each choice)
   - Event boundaries (after each event emission)
   - Game end (outcome projection)
5. **Error capture**: All exceptions are caught and emitted as error projections.

### Reproducibility requirements
- Repeated export of the same game (same seed, same seats, same sources) must be byte-identical.
- All projections must be deterministic given the same game state.
- Hidden information must be consistently redacted for each viewer.
- Option IDs must be stable across projections.
