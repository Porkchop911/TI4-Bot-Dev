## What §5.2 asked for, and what was actually outstanding

§5.2 prescribes building features from `Observed::redacted_for(player)` and emitting
`opponent-secrets-held:<n>` for opponents. Splitting that into requirement and mechanism:

| §5.2 clause | status on arrival | why |
|---|---|---|
| acting seat sees own secrets | already held | M09-021 routes them as explicit records, bound to the choice owner in live play |
| opponents expose no identities | already held, more strongly than asked | `Observed` carries no private data of any seat — see below |
| build from `redacted_for(player)` | **mechanism no longer exists** | removed in M09-021 round 2 as a defect |
| emit `opponent-secrets-held:<n>` | **not built** | this package |

`Observed::redacted_for(viewer)` was removed during F-M09-021-1 round 2: a public method taking a
caller-chosen viewer and returning that viewer's unredacted cards is the same defect as the finding
it sat beside. Its successor `SeatObservation::held_state()` was removed at round 4, because a
capability that hands out a copy of the state is a state handle, and that copy's redaction was
defeated by set complement over the unredacted `secret_deck` (measured: five of five opponents'
aliases recovered).

So "build from a redacted view" is no longer available *or* desirable. The boundary that replaced
it is stronger: there is no view to redact, because the public type carries nothing private. This
package delivers §5.2's requirement and not its mechanism, and records the divergence rather than
reinterpreting the plan to match what exists.

## What was implemented

`opponent_facts(seen, player)` emits one family:

```
opponent-secrets-held:<n> = <number of opponents holding exactly n secrets>
```

The count keys the name; the value counts the opponents at that count. No opponent is named — a
per-seat feature would be a board identity meaningless in the next game, the same reason bare
option ids are excluded from the explicit path. Everything read comes from `PublicSeat`, which
carries counts and no card identity of any kind.

A count of **zero is emitted**. An opponent who has scored every secret they held is a materially
different threat from one sitting on three, and "nobody left to score" is a fact about the position
rather than the absence of one. The module's zero-skip convention concerns zero *values*; a bucket
that exists always holds at least one opponent.

Emission follows the F-M09-021-2 structure: bare on every option under every crossing mode
including `StateCross::None`, crossed copies under `state-kind:` / `state-option:`. Computed once
per choice — it walks every seat.

## Tests added

| test | what it establishes |
|---|---|
| `opponent_secrets_expose_counts_and_never_identities_in_any_feature_set` | three seats holding 2 / 1 / 0 known secrets; for each seat, **both** the explicit path and the legacy hashed name path are extracted and no opponent alias appears in either |
| `opponent_secret_counts_are_a_seat_anonymous_distribution` | swapping which opponent holds which count leaves the facts identical; changing the distribution changes them |
| `opponent_counts_survive_state_cross_none` | the §4.1 contract |

**Both halves of test 2 are load-bearing.** Anonymity alone is satisfied by a constant. The
sensitivity half — `assert_ne!` on a changed distribution, then an exact assertion on the new value
— is what makes the anonymity assertion mean something. This is the X1 lesson from M08-021, where a
guard test's fixture was three identical rows and both its assertions were unfalsifiable.

**On the non-vacuity check in test 1, recorded because the first version was wrong.** The draft
asserted that seat a's own secret alias appears in its features. It failed: a held secret reaches
the features by alias only once it is *satisfied* (the met channel); before that it contributes
family-token progress instead. The fix was not to weaken the assertion but to replace it with a
stronger one that does not depend on satisfaction — remove the acting seat's secret records and
show the feature set changes. If secrets were inert for the acting seat, no opponent alias could
appear either, and every assertion in the test would pass by measuring nothing.

## Limitations — stated, not hidden

1. **The legacy hashed path is proven by output, not by construction.** Test 1 extracts its readable
   names and shows no opponent alias appears. That is a measurement on one fixture position, not a
   proof over all positions. The structural argument — the function takes no secret records and an
   `Observed` that carries none — is what actually makes it safe; the test guards against that
   argument becoming false. Both are recorded because neither alone is sufficient (M08-019 Y1).
2. **One fixture position.** The alias-absence measurement runs on a single three-seat position
   with one choice kind. A sweep across choice kinds and positions would be stronger and is not
   what this package did.
3. **`opponent-secrets-held:0` is a design choice, not a plan instruction.** §5.2 writes
   `opponent-secrets-held:<n>` without saying whether n = 0 is emitted. The reasoning is above; a
   reviewer who disagrees should say so, since it changes what the feature says about a seat that
   has scored out.
4. **No cost measurement.** `opponent_facts` walks every seat once per choice. Unmeasured, like
   M09-022's fleet parsing.
