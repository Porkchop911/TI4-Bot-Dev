### F-M09-020-1 — unified boundary over one immutable buffer

Design: one `fs::read` per pool feeds, in order, checksum verification, the role gate
(`artifacts::verify_pool_role_bytes` over those exact bytes), and parsing
(`MapPool::load_verified` from those same bytes). No consumer reopens the path after approval.
Error precedence at `run_panel` is preserved (checksum mismatch before role violation).

- `crates/ti4-sim/src/artifacts.rs`: new `verify_pool_role_bytes(bytes, allowed)` (pure) and
  `read_and_verify_pool_role(path, allowed) -> Vec<u8>`; existing `verify_pool_role` now delegates
  to the byte-level function.
- `crates/ti4-sim/src/maps.rs`: new `MapPool::load_verified(path, bytes)` — parses an already-read
  buffer with the same extension dispatch as `MapPool::load` (declared finding-specific extension).
- `crates/ti4-sim/src/baseline.rs::run_panel`: single read → checksum → role gate → parse from the
  same buffer.
- `crates/ti4-training/examples/stage2_training.rs --map-pool`: `read_and_verify_pool_role` +
  `MapPool::load_verified` — one read feeds both verification and parse.
