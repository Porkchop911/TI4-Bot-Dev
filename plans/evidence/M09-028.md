## What was built

`crates/ti4-mlp/src/bundle.rs`. A bundle is a directory, per §4.4:

```
checkpoint-<update>/
  trunk.safetensors      W1 b1 W2 b2
  readout.safetensors    w_shared b_shared delta b_delta
  value.safetensors      omitted for batch_mean
  embedding.safetensors  the 33x16 identity table
  slots.json             the accepted vocabulary, verbatim
  manifest.json          written last
```

`safetensors` via `tch`'s own reader/writer — no new dependency, no code execution on load.

**Manifest-last.** Staging sibling -> tensor files, each re-read and fsynced through a
**write-opened** handle -> `slots.json` -> `manifest.json` fsynced last -> one directory rename.
`FlushFileBuffers` needs `GENERIC_WRITE`, so syncing through `File::open` fails with access denied
on Windows; that cost a round of test failures and is why the handle is opened for write.

**The recovery rule is the first thing `read` does.** A directory with no readable `manifest.json`
is incomplete by construction — nothing else is inspected, nothing is repaired, nothing is deleted.
`latest_complete` skips `checkpoint-<n>.tmp` siblings by name: a staging directory is precisely the
one that must not be resumed from, even when it looks complete.

**Validation order.** Directory contents (closed name set, no symlinks via `symlink_metadata`, no
nesting, size caps) -> schema and dtype -> heads and factions as exact positional lists -> `slots.json`
checksum and `slots_sha256` -> tensor checksums -> tensor shapes and dtype -> unexpected-tensor
sweep. Only then is an `Actor` constructed, so a rejected bundle never half-loads.

`slots_sha256` gets its own check beyond the file checksum because §4.4 names it "the single most
likely silent corruption — same weights, different feature meaning". Nothing about the tensors is
wrong in that case.
