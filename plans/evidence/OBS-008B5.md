## Result

1. **The finding.** While scoping this producer, a genuine representation-doctrine violation
   turned up: `bombardment_target`'s option id *is* the targeted seat's raw `PlayerId`
   (`ChoiceOption::labelled(player.as_str(), ...)`), and nothing suppressed it from the generic
   `option:` token pipeline every option's id and label already pass through — unlike the board
   identities that pipeline's existing `dropped` set was built to catch. A player id is an
   arbitrary per-game seat label; a policy able to key on the literal token `option:b` could
   memorise a seat label that means nothing between games, exactly the failure OBS-005's opponent
   slots exist to prevent for the rest of the observation surface.
2. **Board context.** `bombardment_target_question` now attaches `system`/`planet` payload — this
   decision previously carried no payload at all, so even the generic board-fact pipeline never
   reached it.
3. **The fix.** `explicit_option_features_with`'s `dropped` set, which already strips a board
   identity out of a composite `verb|argument` id's argument half, gains a second branch: for
   canonical kind `bombardment_target`, the *entire* id is dropped, because there is no
   `verb|argument` split here — the whole id is the identity. Since `dropped` filters the combined
   id-and-label token set, this also removes the seat from the label ("b's units") — a fix at only
   the id level would have left the label leaking it.
4. **The replacement fact.** `bombardment_target_features` parses the option id back into a
   `PlayerId`, looks up its position in `seen.opponent_slots(player)` (OBS-005: relationship, then
   initiative, then seating order), and emits `combat:target-slot-{index}` under the existing
   `combat` family — the same kind of bounded, cross-game-stable fact OBS-006 already uses for
   board presence.
5. **Scope boundary.** This fix is deliberately scoped to `bombardment_target`, the one producer
   this audit found and confirmed. A grep across the engine crate during scoping found `.as_str()`
   used alongside `ChoiceOption::labelled` in roughly twenty files; whether any other producer's
   option id or label carries a raw player identity the same way is not established here and is
   recorded as a residual for a dedicated audit (in the spirit of `OBS-002B_ALIASING_CENSUS.md`),
   not silently fixed everywhere in this package.

## Focused evidence

- `invasion.rs::obs008b5_bombardment_target_options_carry_their_system_and_planet`: every option
  from `bombardment_target_question` carries the correct `system`/`planet` payload; the option ids
  are still the targeted seats (`{"b", "c"}`), confirming the engine-routing identity is untouched.
- `features.rs::obs008b5_bombardment_target_options_use_a_slot_not_a_raw_identity`: on a fixture
  where the targeted seat shares a system with the actor (an OBS-005 combat counterpart, sorting
  to slot 0), the emitted names include `combat:target-slot-0`, **exclude** any `option:b`-shaped
  literal-identity token, and include an `option-system:*` fact from the `system` payload.
