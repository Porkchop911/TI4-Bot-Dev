## What was done

1. **Content-driven face-up model** (`promissory.rs`). The hard-coded
   `FACEUP: &[&str] = &["an", "convoys"]` is replaced by `is_play_area(content, note)`:
   a faction corpus record applies only to its own owner faction; a generic `<color>` record
   applies under every owner faction; unknown or malformed keys are not face-up. Deterministic,
   read-only with respect to game state. `take()` now takes the content store and marks a
   received note face-up iff `is_play_area`.
2. **baf filter** (`combat.rs::note_holdings`). The issuer set per holder now requires
   `state.promissory_faceup.contains(note)` in addition to the M06-024 F1 issuer resolution
   (`owner_of` → `seat_of`, unseated owner yields no phantom id). Tactical-action-start snapshot
   timing from M06-021a is untouched; `support_holders` unchanged (sftt play-area by construction).
3. **sb filter** (`secrets.rs::rival_note_issuers_count`). The count now requires the note to be
   face-up, and issuer resolution uses `owner_of(note)` directly — the faction name embedded in
   the key itself. This also fixes a latent defect (K1, same class as M06-024 F1): the old code
   looked up the corpus record by alias and read its `faction` field, which misses every generic
   `<color>` note (its corpus id carries the `<color>_` prefix), so held Alliances never counted.
   The accepted deduplication semantics (BTreeSet keyed by seated player id or faction name) and
   the non-zero-threshold contract are preserved; own-faction notes still excluded.
4. **Mechanical threading** (`transactions.rs`). `give()` takes the content store and passes it to
   `promissory::take`; one test call site updated. No behavior change beyond requirement 1.

### Scope extension declared (before commit)

`crates/ti4-engine/src/transactions.rs` is not in the spec's original writable list. It became
writable as a mechanical consequence of requirement 1: `promissory::take`'s signature gained the
content parameter, and `give()` is its only production caller outside tests. The change is
signature threading plus one test call site — no logic. Declared here per AGENTS.md; the Tier-C
reviewer should confirm it stays within that bound.

## Behavior change versus M06-023 / M06-021a (recorded, not waived)

baf and sb now count only play-area notes. Consequences:

- baf can no longer fire on hand-held faction notes (stricter than M06-021a/M06-024-F1 behavior),
  but **can** fire on the eight faction play-area notes that previously never went face-up —
  including Terraform, named by the card's own notes field. Net direction is not predictable a
  priori; it depends on which notes actually change hands in play.
- sb likewise: hand-held rival notes stop counting (stricter); generic Alliances now count where
  the old record lookup missed them (K1 fix).
- **All downstream VP/clearance numbers are non-comparable until re-baselined.** Reference points:
  pre-M06-025 baseline mean VP per seat **2.935** (adjudicator's J2, recorded in the M06-024
  ledger); post-M06-025 probe run on the same protocol reports **2.958** (`feat_activation_probe`,
  see `plans/M06-024_OPEN_REVIEW_ITEMS.md` §J1 resolution). The +0.023 delta is within harness
  noise and not a claim of improvement.

### L1 — MEDIUM (evidence, not defect) · eight of nine faction play-area notes cannot fire under D11's roster — **recorded**

Measured over the same 150-game panel: only `an` (43 face-up observations) and `convoys` (42)
ever go face-up — exactly the two the old hard-coded list had. Structural, not statistical: of the
nine faction play-area notes, only `convoys` belongs to a faction in D11's six-faction roster
(sol, letnev, xxcha, hacan, jolnar, l1z1x); empyrean, mentak, naalu, nekro, titans,
deepwrought and crimson are not seated. The change is still right — the hard-coded list was wrong
on its face, and the corpus-driven model is what makes a future roster widening work without
another engine change — but the measured effect on those eight notes is necessarily zero **by
construction rather than by rarity**. This is the inverse of J1: reachability there had to be
proven; here it is provably blocked by the roster.

**Standing re-check condition (recorded per L1's required action):** D11 roster widening is
explicitly out of scope for this branch (`docs/MLP_PLAN.md` §12), so no current package widens
the roster. Any future package that seats a faction outside the six must re-verify baf/sb
activation for the eight faction play-area notes (blood_pact, pop, gift, antivirus, terraform,
dark_pact, shareknowledge, sever) before citing their scoring behavior.

### L2 — INFORMATIONAL · M06-023's measured sb gain was counting hand-held notes — **recorded**

sb across the milestone: 49/56 = 88% (before H1) → 51/56 = 91% (after H1, no play-area filter)
→ 49/56 = 88% (after this package). The three seats H1 appeared to gain were hand-held faction
notes the card excludes; the return to 88% is the filter working, not a regression. baf held at
11/58 = 19% throughout H1/F1/M06-025. A line has been added to `plans/evidence/M06-023.md` so the
91% figure is not cited later as a durable improvement.

### L3 — INFORMATIONAL · `note_holdings` has no own-faction guard — **resolved (comment)**

Unlike `rival_note_issuers_count`, `note_holdings` does not exclude a seat's own notes. Harmless:
baf tests `notes[winner].contains(loser)` with winner ≠ loser, and a seat can never hold its own
faction's note (deal keeps own notes in hand; factions are unique per seat). Resolved at the
author's discretion by recording the asymmetry as deliberate in a comment at
`combat.rs::note_holdings`, rather than adding a guard for an unreachable state.
