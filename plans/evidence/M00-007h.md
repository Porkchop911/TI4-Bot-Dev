## NDJSON schema for Oracle exporter (M00-009)

### File format
- One JSON object per line (NDJSON), encoded as ASCII with compact separators and a final newline.
- The first object is a deterministic `header`; every later object has a `type` field identifying
  a projection and objects are ordered chronologically by game time.
- The header contains `schema_version`, `oracle_commit`, `game_id`, `seed`, `seats`, `sources`,
  and `export_scope`. It deliberately has no wall-clock export timestamp: a timestamp contradicts
  the required byte-identical repeatability.

### Projection types
1. `state` — Game state snapshot (M00-007a)
2. `view` — Per-player redacted view (M00-007b)
3. `choice` — Decision point (M00-007c)
4. `event` — Game event (M00-007d)
5. `outcome` — Game outcome (M00-007e)
6. `error` — Error occurrence (M00-007f)

### Schema version
```json
{"type":"header","schema_version":"1.0.0","oracle_commit":"37061c511a4780d4c0719e0342533a498cd4b457","game_id":str,"seed":int,"seats":[str],"sources":[str],"export_scope":str}
```

### Projection ordering
1. Initial state (type: "state")
2. For each turn/round:
   a. State snapshots at phase boundaries
   b. Choice events (type: "choice")
   c. Game events (type: "event")
   d. View snapshots (type: "view") at choice boundaries
3. Final outcome (type: "outcome")
4. Errors (type: "error") wherever they occur

### Reproducibility requirements
- Repeated export of the same game is byte-identical
- All projections are deterministic given the same game seed
- Hidden information is consistently redacted for each viewer
- Option IDs are stable across projections
