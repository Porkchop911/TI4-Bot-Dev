### Differences from the oracle

| Difference | Reason |
|---|---|
| `build` returns `Result` rather than raising. | The oracle raises `ValueError("... rings hold ...")`; the message is preserved in `GalaxyError::TooManyTiles`. An unknown system id is also an error here — the oracle would raise `KeyError` from a dict lookup, which is the same failure with a worse message. |
| `distance(a, b)` between two *systems* is exposed. | The oracle only offers `coord_of(x).distance(...)`. Same arithmetic; documented as geometric, not a movement range, because wormholes make tiles adjacent without making them close. |
| `Galaxy` stores each system's wormhole kinds at build time. | So adjacency does not need the store threaded through every call. The values are copied from the same records the catalogue hands out. |
| Hyperlanes are listed via `Galaxy::hyperlanes()`. | The oracle silently does not model them. Making the exclusion visible is cheap and stops a caller assuming hyperlane tiles route anything. |

## Finding: twelve planets have no printed tile

`every_printed_planet_names_a_system_that_exists` initially failed on 12 planets whose
`tileId` is `null`: `mirage`, `custodiavigilia`, `avernus`, `thundersedge`, `triad`,
`illusion`, `phantasm`, and `ocean1`–`ocean5`.

These are not dangling references. Each is a planet placed onto a tile *during play* —
Mirage from exploration, Custodia Vigilia from the Custodian relic, the rest from Thunder's
Edge tokens — and each has a matching record in the `tokens` category. Modelled as
`Planet::is_placed_during_play()` and pinned by
`twelve_planets_are_placed_during_play_rather_than_printed_on_a_tile`, rather than
allowlisted. `planets_in` correctly excludes them from every system, which is asserted
separately: a placed planet appearing on a printed tile would be a real bug.

## Open findings

1. **No independent review.**
2. **Hyperlanes are not modelled.** The corpus flags the tiles but carries no path data.
   Adjacency through a hyperlane will be wrong until that data is sourced. Listed, not
   silently omitted.
3. **`Galaxy::build` is spiral placement, not map setup.** The oracle says the same: real
   setup needs `map_templates` (34 records, currently unread) and drafting. M04-004.
4. **Nothing consumes this yet.** `ti4-engine::tactical.rs` still hardcodes
   `calculate_distance() -> Ok(1)`. Wiring it in is the next package and will require the
   state model to hold a `Galaxy`.
