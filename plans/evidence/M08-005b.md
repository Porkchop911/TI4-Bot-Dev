   exists.
2. When no activation is useful, the bot keeps the offered set rather than creating an empty

3. Board-aware movement prefers a useful arrival and can finish movement instead of adding an
   idle hull to an already-secured system.

## Implementation

- `Observed` now exposes the public active system and a public-board reachability query. The query
  reuses `MovementRules` with the public map, board occupancy, command tokens, and laws; it does
  not expose a `GameState` or unplayed card effects.
- `ScoredBot::choose_seeing` uses the existing dispatcher as a blind fallback, adds
  `system_value` to activation scores, and applies the oracle's shortlist rule: if at least one
  activation can move a ship or produce there, unreachable non-producing activations are removed
  only from the bot's candidates.
- Movement scores the selected hull, destination prize, useful lift, and whether it has a job at
  the active system. An idle reinforcement is deliberately less valuable than `finish movement`.
- The old stale policy documentation now records the board-aware path and the remaining M08-005c
  tactical areas.

## Compatibility evidence and known differences

- The activation filtering boundary follows the oracle's `_worth_considering`: it changes the
  bot's sampled candidate set without changing engine legality or the options a human receives.
- `choose` and `choose_seeing` share the same kind dispatcher; any window still using plain
  `choose` retains the prior blind behavior rather than acquiring an untested gap.
- The public observation query returns only a derived route result, not an owned state reference
  or private holding. It intentionally excludes unplayed card effects because this scored bot is
  not permitted to inspect a hand.
- The diagnostic is a behavioral signal, not a parity or performance claim. It improved the
  current score distribution to a maximum of three points, but games still exhaust objectives;
  cargo, landing, combat, production, economy, and objective planning remain necessary.
