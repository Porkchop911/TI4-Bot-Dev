## Invariants and compatibility contract

- A nested `Resolver::emit` completely resolves its WHEN/event/AFTER sequence before the invoking
  ability returns and the outer window resumes.
- The current root-to-leaf `(event_type, id)` chain is always LIFO-cleaned, including after an
  illegal choice or nested-depth failure.
- The default hard limit permits 100 simultaneous events. Attempting event 101 returns an
  explicit `TimingError::NestedEmissionDepthExceeded` with the maximum and the open chain; it
  never wraps, silently truncates, or panics.
- Ability effects are now `Result`-returning callbacks, so a nested failure propagates through
  every outer resolver call rather than being converted into a panic or ignored result.
- An inner cancellation cancels only that inner event. The Python event model has no upward
  cancellation propagation, so the outer event still follows its own after-window semantics.

## Tests added

1. An outer WHEN ability emitting an inner event observes the inner AFTER before outer event resolution.
2. An inner cancellation suppresses only the inner event and leaves the outer AFTER window available.
3. A small configured depth limit reports the exact open chain and leaves the resolver usable for
   a later root emission.
4. The default limit refuses the one hundred and first event, with a 100-event chain from root to leaf.

## Implementation and compatibility evidence

- `Resolver` maintains a private `emission_stack` of `(event_type, id)` pairs. Each successful
  root or nested entry pushes before any WHEN candidate runs and pops through one exit path after
  normal completion, cancellation, a choice error, or a nested error.
- Trace emission now records the explicit depth: `emit TYPE#ID (depth N)`. Existing resolution
  lines remain unchanged and show the inner event's ordinary resolution before the outer one.
- Rules use a fallible callback type. The only new failure variant contains both `maximum_depth`
  and the complete open chain, allowing callers to distinguish it from a decider legality error.
- The Python oracle does not itself impose this cap. The bound is the M03 plan's explicit Rust
  safety requirement; it is deterministic and does not change any valid trace below 100 open events.
