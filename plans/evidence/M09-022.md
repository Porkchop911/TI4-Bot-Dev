## Corpus measurement this package rests on

Measured against the embedded corpus at `DEFAULT` (= `FULL`) before implementation, and pinned by
test afterwards.

| quantity | measured |
|---|---|

| records failing the selectable-seat predicate | 1 (`neutral`) |

| distinct under abilities only | 32 / 34 — collision `keleresa = keleresm = keleresx` |
| + starting tech | 32 / 34 — same |

| **+ starting fleet, home planets, commodities** | **34 / 34 — none** |

Two deviations from §5.3 as written, both recorded rather than silently absorbed:

1. **§5.3 says 33 playable seats; the corpus holds 34 faction records.** The extra one is
   `neutral`, the Thunder's Edge neutral-units record: empty `homeSystem`, empty `startingFleet`,
   empty `homePlanets`, no abilities, no leaders, no promissory notes, zero commodities, and none
   of the playable-seat fields (`complexity`, `preferredColours`, `priorityNumber`, `wikiURL`).
   Excluding it gives exactly 33. §5.3's number is correct about seats; it simply predates this
   record or never counted it.
2. **The exclusion is a predicate, not a name.** `is_selectable_seat` tests for a non-empty
   `homeSystem`. Exactly one record fails it today — verified independently against
   `startingFleet` and `homePlanets`, which are empty for the same single record and no other. A
   deny-list naming `neutral` would let the next non-seat record through in silence.

The separation structure §5.3 reports is otherwise reproduced exactly, including the single Keleres
collision and the row that resolves it.

## What was implemented

`ability_facts(seen, player)` emits six families for the acting seat only:

| family | value | source |
|---|---|---|
| `ability:<alias>` | 1.0 | `abilities` |
| `faction-start-tech:<alias>` | 1.0 | `startingTech` |
| `faction-tech:<alias>` | 1.0 | `factionTech` |
| `faction-start-unit:<unit>` | count | `startingFleet`, parsed via `Faction::deployments` |
| `faction-home:<planet>` | 1.0 | `homePlanets` |
| `faction-commodities` | value | `commodities` |

Emission follows the structure F-M09-021-2 settled: bare names on **every option under every
crossing mode** including `StateCross::None` (the §4.1 nonlinear-trunk contract), plus crossed
copies under `state-kind:` / `state-option:` for linear-schema delivery. The two namespaces are
disjoint by construction. Facts are computed once per choice in `ChoiceContext`, not per option —
the fleet string is parsed once rather than thirty-odd times on an activation choice.

The six families were added to `EXPLICIT_FIXED_FAMILIES` (27 → 33), a reviewed extension of the
closed grammar. Every legacy name is unchanged.

## Invariant 2 — the active content domain

The faction record resolves through `seen.content()` and `seen.sources()`. It does **not** call
`ContentStore::embedded()` and does not name a scope. This is the M08-019 Y2 defect class
(`annexable()` reading the compiled-in corpus while taking a live position) and the M09-021 AA1
class; `ability_facts_follow_the_active_source_scope` exists so a regression fails a test rather
than passing every one. `bastion` is a Thunder's Edge seat: in scope under `DEFAULT`, out of scope
under `POK`, so a hardcoded scope of either value fails exactly one of the two assertions.

The **store** half of the invariant is currently argued from the call rather than proven by a
second store; see Limitations.

## Limitations — stated, not hidden

1. **The store half of invariant 2 is not proven by test.** The scope half is. Proving the store
   half needs a second `ContentStore` built by `from_dir` over an edited corpus copy; `from_dir`
   reads a `manifest.json` alongside the JSON, so whether an edited copy loads was not established
   here. Until it is, "resolves through the active store" rests on reading the call, which is
   exactly the standard of evidence M08-019 Y1 showed to be insufficient. Recorded as an open item
   rather than claimed as verified.
2. **Extraction cost was not measured.** `ability_facts` parses the starting fleet once per choice.
   M09-021 established that extraction is already several times the engine's per-decision cost on a
   feature-heavy fixture, so this is not obviously negligible and no claim is made that it is.
   M09-029's gate is where it would show up.
3. **Emitted-feature separation is measured on a one-option fixture** per seat. The decomposition
   is option-invariant by construction, and `ability_facts_survive_state_cross_none` checks the
   multi-option case separately, but the 33-way separation itself was not re-measured across
   crossing modes.
