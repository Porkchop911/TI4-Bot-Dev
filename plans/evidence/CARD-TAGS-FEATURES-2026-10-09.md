## What was built

1. **Artifact** `crates/ti4-policy/src/card_tags.json`: `{"schema":1,"taxonomy_version":1,"tags":[138 sorted],"cards":{"<kind>:<id>":[sorted tags]}}`, compact, sorted keys, LF, no trailing newline. 896 cards keyed `(kind, id)`; `deal-enforcement` removed from taxonomy and cards. Generated by a scratchpad script (`gen_card_tags.py`, run twice, same bytes). Embedded with `include_str!`.
2. **Module** `ti4_policy::card_tags`: `tags_of(kind, id) -> &'static [&'static str]` (unknown = empty), `all_tags()`, `taxonomy_version()`, `kind::*` constants; parsed once (`OnceLock`).
3. **Family A `card-tag:<tag>`** (`projection::card_tag_seat_facts`): the acting seat's own faction cards, value `features::count_value(n)` (helper made `pub(crate)`, formula unchanged), BTreeMap-sorted, zero-skipped, acting seat only. Emitted next to the seat facts (`interned_seat_state`), NOT in `features.rs`: the schema-4 extractor output is unchanged (only a visibility edit to `count_value`). Card set (`faction_cards`), resolved via `seen.content()`/`seen.sources()`, never `ContentStore::embedded()`:
   - abilities (`factions.abilities`), faction techs (`factionTech`) plus any `startingTech` whose technology record has `faction == alias` (none exist in the corpus today, so currently a no-op), units (entries of the faction's `units` list whose unit record has `faction == alias`: flagship, mech, faction infantry/destroyer... plus unit upgrades = records with `faction == alias` and `upgradesFromUnitId`), leaders (agent, commander, hero), breakthrough (`breakthroughs` records with `faction == alias`), faction promissory note(s).
4. **Family B `card-tag-opt:<tag>`** (`projection::card_tag_option_facts`), value 1.0, next to `action_facts_within` (called from the same per-option place in `mlp_choice_features_with`). See the table below.
5. **Gating**: `mlp_choice_features_with(.., card_tags: Option<&CardTagInput>)` and `mlp_option_features_with(..)`; `mlp_choice_features` / `mlp_option_features` are wrappers passing `None` (the 16 caller files are untouched). Deviation from a bare `bool`: the public `Observed` cannot read a hand (private by design), so enabling needs the acting seat's hand; `CardTagInput { held_action_cards, held_promissory_notes }` carries exactly `SeatObservation::held_action_cards()` / `held_promissory_notes()`, and `Some(..)` is the enable flag. `projection::card_tags_enabled_for(&Vocabulary)` is true iff the vocabulary places every `card-tag:<t>` and `card-tag-opt:<t>` (all-or-nothing; a partly migrated vocabulary is refused). `MlpBot` computes it once in both constructors (`sharing`, `batched`) into a `card_tags` field and uses it through one helper `MlpBot::project` at both feature call sites (`decide`, `choose_package`).
6. **Roles**: `("card-tag", Transferable)` and `("card-tag-opt", Transferable)` added to `FAMILY_ROLES` (now 50) with comments; `CLOSED_FAMILIES: [&str; 2]` added. `the_classification_covers_exactly_the_registry` now asserts classified == OOV registry ∪ `CLOSED_FAMILIES`, length == registry + closed, and that no closed family is in the OOV registry.
7. **Names list**: `crates/ti4-policy/examples/card_tag_names.rs` prints `projection::card_tag_names()` (276 names, byte-sorted).
8. **Identity check** `crates/ti4-mlp/examples/card_tags_identity_check.rs` (CPU).

## Family B: mapped and unmapped option kinds

Each mapped kind has a test that obtains the options from the engine's own constructor (not hand-built options): `draft::strategy_options`, `strategy_cards::primary` with a capturing decider, `action_cards::available_actions`, `reactions::arm` + a real `SYSTEM_ACTIVATED` window with a capturing decider, `leaders::component_actions`, `diplomacy::builder::item_options`.

| option kind | option id | card | hidden-info rule | test |
|---|---|---|---|---|
| `research` | technology id | `technology:<id>` | technology tree is public | `a_research_option_carries_that_technologys_tags` |
| `strategy_card` | corpus strategy-card id | `strategy_card:<id>` | unclaimed cards are public | `a_strategy_card_option_carries_that_cards_tags` |
| `component` | `action_card|<n>` | `action_card:<hand[n]>` | `n` indexes the acting seat's `held_action_cards`; out of range or no hand supplied = nothing | `a_played_action_card_option_resolves_through_the_seats_own_hand` |
| `action_card` (reaction window) | alias | `action_card:<alias>` | only if the alias is in the seat's `held_action_cards` | `a_reaction_card_option_carries_the_card_tags_only_when_held` |
| `component` | `component|leader|<leader>` (exactly 3 segments) | `leader:<leader>` | the seat's own leader (engine offers only its own) | `a_leader_component_option_carries_that_leaders_tags` |
| `diplomacy_item` | `diplomacy|note|<note>` | `promissory:<alias>` (generic `cf/ps/ta/an` -> `<color>_<alias>`) | only if the note is in the seat's `held_promissory_notes` (so an "ask for" item naming the partner's note gets nothing) | `a_promissory_note_item_carries_the_notes_tags_only_when_held` |
| `diplomacy_item` | `diplomacy|card|<alias>` | `action_card:<alias>` | only if held | covered by the same hand logic (`holds_card`); no dedicated engine-driven test (Arbiters/Black Market setup not built) |

Skipped, with reasons:
- `component` / `action_card|salvaged|<alias>`: public Garbozia yard, not mapped; asserted to produce nothing. No test drives a real salvage decision.
- `component` / `component|leader|yssarilagent|<agent>` (Ssruu's borrowed agent): four segments; asserted to produce nothing.
- Per-faction `component` ids (`faction_abilities::ACTION_KIND`, relics, arborec, cabal, ...): ad hoc ids, no single provable id-to-card mapping.
- Leader-specific decision kinds (`leader_hacanhero_free_production`, `use_leader_timed` prompts): per-leader ad hoc kinds/ids.
- `offer` / `transaction` payload `promissory` / `action_card` (`transactions.rs`): the payload does not say which side gives the card, so a card the seat may not see could be named.
- Playing a promissory note (`action_notes_in_hand` call sites: crimson, deepwrought, empyrean_units): faction-specific option ids/kinds.
- Agenda votes (`vote`), relic and exploration options: out of the requested set.
- `ability`, `faction technology` and `unit` as options (e.g. producing a faction unit): not requested; produce-unit option ids are unit types, not unit cards.

Reach in real play (identity check, 3 seeded games): 619 of 11,657 scored options carried an option tag (research, strategy-card draft, component action cards, reactions).

## Gating design, and every path that builds the same features

Old bundles: the vocabulary places no card-tag name -> `card_tags == false` -> `mlp_choice_features` -> identical vectors (`the_gate_leaves_the_legacy_projection_untouched`; `None` is `assert_eq`-identical to the wrapper, and with `Some` the vectors are the legacy names plus only `card-tag:`/`card-tag-opt:` names).

Train == play: all MLP acting, PPO recording and rollout code goes through `MlpBot` (`ppo_update`, `trade_arena`, `rescue_imitation`, `clearance_eval`, ... all construct it via `MlpBot::sharing`/`batched`). `MlpBot::record` stores the same `SparseOption`s the policy was scored on, and `ppo_update` replays those stored options (no re-extraction), so features at train time equal features at play time by construction. The critic input is the separate `critic-state:*` family and is unaffected. `ti4-training` rollout.rs needed no change.

Deliberately left on `false` (they call `mlp_choice_features`, the legacy wrapper):
- `ti4-mlp/examples`: `capture_offline_pilot`, `distill_mlp` (offline BC/corpus feature capture), `cpu_gate`, `paired_gate` (cost gates), `mlp_decide`, `vocab_census`, `inference_cost_support/*` (a vendored copy of the projection with its own 47-row `FAMILY_ROLES`), and `tests/critic_invariance.rs`. Training or labelling with `distill_mlp`/`capture_offline_pilot` against a migrated bundle would see no card tags (mismatch with play) until they are switched to `mlp_choice_features_with`; deliberately not done here (separate decision, per-tool).
- `ti4-review/src/lib.rs:713` (a reviewer-side scorer) and `ti4-training/src/vocabulary_corpus.rs:238` (name discovery for building a vocabulary; fresh vocabularies do not contain card tags until a migration appends them). `ti4-review/src/lib.rs` has someone else's uncommitted edit, so it was not touched; a migrated bundle's reviewer scoring at that site would not include tags (the review path that seats an `MlpBot` does).
- `ti4-policy/src/inference.rs:367` (linear `LearnedBot` recording of the MLP view): the linear bots do not use card tags.

## Identity check (CPU, debug build)

```

  --migrated out/card-tags-migrated-20261009/checkpoint-20 --seeds 3 --rounds 4 --stride 3
```

Six-seat roster (sol, letnev, xxcha, hacan, jolnar, l1z1x), seeds 920000000-920000002, 4 rounds, temperature 0.001. The source bundle's bots play; at every third decision with two or more options the probe projects with tags off (source) and on (migrated), scores both actors on the resolved head, and compares logits. Then the same games are replayed with the migrated bundle's own bot (which enables tags itself from its vocabulary) and traces compared.

Max |Δlogit| is exactly zero (zero input rows contribute `0 * value`). An earlier first run (seed 920000000, first 600 decisions only, no stride) also gave 0.000e0 / IDENTICAL.

Limits of this check: the probe scores the base projection only (it does not add the arena battle facts / deal values / power facts the bot appends); the same appends happen in the bot replay, which compared every offered option set and chosen option (IDENTICAL). It has no negative control (no deliberately perturbed bundle was run to show the probe detects a nonzero difference).
