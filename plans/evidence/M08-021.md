## What was done

Additive module `crates/ti4-sim/src/behavior.rs` (registered in `lib.rs`; no other file under
`crates/` changed — `run.rs`, `play()`, and `GameResult` untouched, per the spec's non-goals).
The suite:

1. **Fixed seed set** — 30 seeds `812_001..=812_030` (committed constant; consecutive integers in
   an unused range, no other property claimed).
2. **Protocol v1** — seats `p1`..`p6` on the stable roster, POK scope, `Seats::Scored` (one
   authored bot per seat), `Horizon::default()`. Games end by objective exhaustion in about nine
   rounds; all thirty v1 games ended cleanly (27 `ObjectivesExhausted`, 3 `VictoryPoints`).
3. **Nine metrics** — `vp_pace` (mean final VPs / rounds, averaged over seeds), `completion`
   (clean endings), `faction_spread` (per-game population std dev of the six seats' final VPs),
   and an action mix: each tactical event label's share of a game's event stream, averaged over
   seeds. Labels: `SYSTEM_ACTIVATED`, `SHIP_MOVED`, `PRODUCTION_RESOLVED`, `INVASION_RESOLVED`,
   `SPACE_COMBAT_RESOLVED`, `TACTICAL_ACTION_BEGAN` (chosen from the v1 census — see below).
4. **Bounds** — 95% bootstrap CIs (2000 resamples per metric, deterministic splitmix64) over the
   baseline's per-seed values, embedded as constants in `baseline_bounds()`. Re-baseline
   discipline is stated in the module docs: old/new side by side here, semantic cause named,
   review approval; an out-of-bounds result on an unchanged tree is a failure to diagnose.
5. **Gate test** — plays the seed set twice, asserts per-seed identity (VPs, rounds, decisions,
   events, ending) *before* any comparison (a flaky bound could otherwise hide engine
   nondeterminism), then checks all nine metrics against the recorded bounds.

**Degenerate bound, recorded decision:** all thirty v1 games ended cleanly, so the bootstrap CI
for `completion` collapses to `[1.0, 1.0]`. That is the intended semantics: `completion` is an
integrity invariant ("every game ends cleanly"), not a statistical interval — any error or
horizon cutoff fails the gate. The non-degeneracy test therefore asserts finiteness and ordering
(`lo <= hi`) for all metrics, with degeneracy legal only when justified by constant baseline
data (documented at the bound's site and in the module docs).

**Per-faction mean VP (v1)** — recorded for the differentiation question: letnev 4.467, jolnar
4.200, xxcha 4.167, l1z1x 4.133, sol 3.900, hacan 2.900. The spread is real (hacan clearly the
weakest seat), which is what makes `faction_spread` a meaningful metric; no action is taken on
it here — bot quality is M08-016's territory, and this suite only pins the baseline.

**Action-label census (v1)** — mean share of each label in a game's event stream:

## Mutation check (required deliverable)

Two mutants were tried on `ScoredBot` (temporary edits to `crates/ti4-policy/src/bot.rs`, both
reverted byte-identical before verification — `git diff crates/ti4-policy/` empty):

**Mutant A — activation base 6.0 → −10.0** (both dispatch paths of the same logical constant).
Result: **no metric moved out of bounds; gate stayed green.** Diagnosis: the position-aware path
adds `system_value` (prize − 0.6·defenders − 0.4·garrison, typically +15..+30 for a home system)
on top of the base, so activation remained positive for most systems — the mutant re-ranked
*which* system to activate first without changing *how often*. Recorded as a sensitivity note:
this suite resolves behavioral drift at the level of action frequencies, pace, and spread — not
within-class ranking. That is the right resolution for baseline comparability (a bot that
activates the same number of fleets in a different order is still the same behavioral baseline).

**Mutant B — pass score 0.5 → 100.0** (`score_action`: the bot passes every action phase).
Result: **gate FAILED as designed**, and the full shifted distribution shows zero CI overlap with
v1 on eight of nine metrics:

## Review resolution (2026-08-23)

Operator-directed Tier B review (`plans/M08-021_OPEN_REVIEW_ITEMS.md`) — **accept with R1
required before commit; R1 resolved in-package.** Independence limitation recorded: no frontier
peer was connected to this session's broker, so the implementing agent performed the review pass
at operator direction (M06-024 precedent); a cross-model check on the bootstrap methodology
specifically remains available as a frontier escalation before M08-019's exit review.

- **R1 (MEDIUM) — resolved:** bounds were embedded at display precision ({:.9}) with nothing
  tying them to the protocol; a consistently-inside transcription error would have passed every
  test. Fixed: full-double re-derivation, named `BOOTSTRAP_DRAWS`/`BOOTSTRAP_SEED`, in-gate
  integrity check (recompute CIs from current data, assert bit-equality). Non-vacuity verified:
  one-digit mutation of an embedded constant failed the gate with the exact diagnostic; revert
  restored green.
- **R2 (LOW) — recorded:** shared RNG stream across metrics' bootstraps correlates their Monte
  Carlo errors; harmless for independent bound checks, noted for any future joint inference.
- **R3 (INFO) — recorded:** gate ~13 s on this machine (parallel workers); serial cost scales
  with seed/core count — same class as M08-018's dev-loop-only campaign.
- **R4 (verified):** no seed-range collision in `crates/`; seating stable (`Table::seated` is
  seed-independent; `run_with` preserves player order and sorts by seed).
- **R5 (verified):** degenerate `[1.0, 1.0]` completion bound is intentional strict-invariant
  semantics.

**Post-resolution verification:** behavior tests 4/0 (~13 s); ti4-sim 31/0; workspace **1,332/0
identical ×2**; clippy -p ti4-sim --all-targets zero warnings; rustfmt clean; `git diff --check
crates/` clean. Temporary re-derivation probe created, used once, deleted.
