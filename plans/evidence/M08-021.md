## What was done

Additive module `crates/ti4-sim/src/behavior.rs` (registered in `lib.rs`; no other file under
`crates/` changed — `run.rs`, `play()`, and `GameResult` untouched, per the spec's non-goals).
The suite:

1. **Fixed seed set** — 30 seeds `812_001..=812_030` (committed constant; consecutive integers in
   an unused range, no other property claimed).
2. **Protocol v1** — seats `p1`..`p6` on the stable roster, `DEFAULT` (= FULL) content scope —
   the simulator runtime's assigned scope; an earlier draft of this record mislabeled it POK,
   corrected 2026-08-23 under M08-019 E2. All v1/v2/v3 bounds were generated under FULL, so no
   measurement is relabeled in either direction — only the protocol claim was wrong.
   `Seats::Scored` (one authored bot per seat), `Horizon::default()`. Games end by objective
   exhaustion in about nine rounds; all thirty v1 games ended cleanly (27 `ObjectivesExhausted`,
   3 `VictoryPoints`).
3. **Ten metrics** — `vp_pace` (mean final VPs / rounds, averaged over seeds), `completion`
   (clean endings), `score_spread` (per-game population std dev of the six final scores —
   within-game dispersion, invariant to which seat scored what), `faction_differentiation`
   (population std dev of the six per-faction mean VPs across the seed set — the spec's
   "spread across the seated factions"; added in the review-resolution pass, finding V3), and an
   action mix: each tactical event label's share of a game's event stream, averaged over seeds.
   Labels: `SYSTEM_ACTIVATED`, `SHIP_MOVED`, `PRODUCTION_RESOLVED`, `INVASION_RESOLVED`,
   `SPACE_COMBAT_RESOLVED`, `TACTICAL_ACTION_BEGAN` (chosen from the v1 census — see below).
4. **Bounds** — 95% bootstrap CIs (2000 resamples per metric, deterministic splitmix64) over the
   baseline's per-seed values, embedded as constants in `baseline_bounds()`. Re-baseline
   discipline is stated in the module docs: old/new side by side here, semantic cause named,
   review approval; an out-of-bounds result on an unchanged tree is a failure to diagnose.
5. **Gate test** — plays the seed set twice, asserts per-seed identity (VPs, rounds, decisions,
   events, ending) *before* any comparison (a flaky bound could otherwise hide engine
   nondeterminism), pins the metric/bounds key sets to be exactly equal (review V4), checks all
   ten metrics against the recorded bounds, and recomputes every bound from current data under
   the named protocol constants (`BOOTSTRAP_DRAWS`, `BOOTSTRAP_SEED`) asserting bit-equality.

## v6 — 2026-08-29: coexistence bombardment becomes a real choice (rules 7, 7.1, 7.2)

Cause: `plans/ENGINE_COMPLETION_PLAN.md` phase 2.4, closed by this tree. On a planet whose
ground forces belong to several players, the bombarding player now chooses, independently for
each bombarding unit, whose units take that unit's hits; each unit's hits are capped by the
chosen target's units and do not spill (7.2). Before this tree, `bombardment_at` announced the
ambiguous case with `debug_assert!(false)` and — in the release builds the simulator runs in —
simply skipped the planet: the dice were consumed and no defender was touched. The suite went
red when `exchangeprogram` (9a6fe0b, batch 4) made coexisting planets reachable in bot play.

The implementation moves the step to the invasion window's paused `ChoosingBombardment` stage:
the window rolls the bombardment plan (dice-consuming half) up front, settles single-owner
planets inline, and pauses per planet while more than one defender still holds units there;
the table answers per bombarding unit, and a unit's surplus hits beyond the target's units are
wasted, exactly as 7.2 prescribes.

Unlike v4 this is a change in **play**, not in measurement: bombs that used to evaporate on a
shared planet now land as kills. The invasion-adjacent action-mix shares drift down by a few
hundredths, `score_spread` and `faction_differentiation` widen, and `vp_pace` rises slightly —
seats trading ground forces on shared planets reach combat outcomes faster. `completion` stays
the strict 1.0 invariant: all thirty games still end cleanly.
