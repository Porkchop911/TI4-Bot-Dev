## Reproducibility verification plan

### Test cases
1. **Same seed, same seats**: Export the same game twice with identical parameters. Verify byte-identical output.
2. **Different seeds**: Export two games with different seeds. Verify different output.
3. **Different seats**: Export the same seed with different faction seating. Verify different output.
4. **Different sources**: Export the same seed with different content sources. Verify different output.

### Verification commands
```bash
# Test 1: Byte-identical output
python tools/oracle_export.py --game-id test1 --seed 42 --output out/export_test1a.ndjson
python tools/oracle_export.py --game-id test1 --seed 42 --output out/export_test1b.ndjson
diff out/export_test1a.ndjson out/export_test1b.ndjson  # Should be empty

# Test 2: Different output for different seeds
python tools/oracle_export.py --game-id test2 --seed 42 --output out/export_test2a.ndjson
python tools/oracle_export.py --game-id test2 --seed 43 --output out/export_test2b.ndjson
diff out/export_test2a.ndjson out/export_test2b.ndjson  # Should show differences

# Test 3: Schema validation
python tools/oracle_export.py --game-id test3 --seed 42 --output out/export_test3.ndjson --validate-schema
# Should pass schema validation
```

### Reproducibility invariants
- All random state is seeded explicitly (no implicit global state).
- All projections are deterministic given the same game state.
- Hidden information is consistently redacted for each viewer.
- Option IDs are stable across projections.
- Event ordering is causal and reproducible.
