# M00-009f — Executable finished-game outcome projection

## Package specification

- **Milestone/package:** M00-009f, outcome projection implementation; dependency M00-007e.
- **Objective:** Project only an oracle state that has actually finished, with deterministic
  victory-point ordering and the oracle's initiative tie-break.
- **Oracle sources/tests inspected read-only:** `engine/game.py`, `engine/objectives.py`,
  `engine/state.py`, `tests/test_objectives.py`, and `tests/test_victory_sources.py` at
  `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 oracle inspection; P1 writes limited to
  `tools/oracle_exporter/`, `tools/test_oracle_state_projection.py`, this evidence file, and
  `plans/EXECUTION_STATE.md`. No network, external state, or oracle writes.
- **Inputs/outputs:** a finished oracle `GameState` and the `GAME_ENDED` reason in; deterministic
  JSON-ready outcome out.
- **Compatibility class:** exact for `finished`, scores, phase/turn/round, and leader tie-breaking;
  the caller supplies the reason because the oracle does not store it on `GameState`.
- **Explicit non-goals:** causing a game to finish, deriving a reason from unrelated state, event
  capture, CLI/NDJSON framing, fixture generation, and parity claims.

## Implementation

- Added `tools/oracle_exporter/projections/outcome.py` and exported `outcome_projection`.
- It refuses unfinished states, so a partial/aborted game cannot be emitted as an outcome.
- Winner selection mirrors `objectives.leader`: highest victory points, with the first player in
  initiative order winning a tie. Score-map keys are sorted for stable serialized bytes. Empty
  player sets produce a null winner, matching the oracle helper.
- Tests cover unfinished-state refusal, initiative tie-breaking, final scores/reason, and
  byte-identical same-state output.
