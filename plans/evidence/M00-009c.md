# M00-009c — Executable redacted-view projection

## Package specification

- **Milestone/package:** M00-009c, view projection implementation; dependency M00-007b.
- **Objective:** Export an oracle `GameView` through its own redaction boundary without recovering
  private information from the underlying game.
- **Oracle sources/tests inspected read-only:** `engine/views.py`, `engine/state.py`,
  `engine/game.py`, and `tests/test_views.py` at
  `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 oracle inspection; P1 writes limited to
  `tools/oracle_exporter/`, `tools/test_oracle_state_projection.py`, this evidence file, and
  `plans/EXECUTION_STATE.md`. No network, external state, or oracle writes.
- **Inputs/outputs:** an oracle `GameView` in, a JSON-ready deterministic projection out.
- **Compatibility class:** semantic. Public state follows M00-009b; the viewer's own action cards
  and unscored secret objectives remain visible while every other player's values are oracle-
  supplied `"?"` markers with counts preserved.
- **Explicit non-goals:** a CLI, NDJSON file framing, complete schema correction, choices, events,
  outcomes, errors, fixture generation, and Rust/Python parity claims.

## Implementation

- Added `tools/oracle_exporter/projections/view.py` and exported `view_projection` from the package.
- `view_projection` reads only `GameView.state` and `GameView.viewer`; it does not access the
  backing game. It first reuses the canonical public-state projection, then appends the two
  private sequences exactly as the redacted view supplies them.
- The local test gives two players distinguishable action cards and secret objectives. It asserts
  the viewer keeps their own identities, the opponent receives only `"?"`, and neither opponent
  identity appears anywhere in the serialized projection. A second test verifies byte-identical
  compact JSON from independent same-seed views.

## Compatibility and review

The pinned oracle declares only `action_cards` and `secret_objectives` private in
`PRIVATE_SEQUENCES`; this projection delegates that policy rather than duplicating it. The old
M00-007b draft refers to obsolete player fields, including promissory-note ownership, so it is not
yet an exact shared schema. No benchmark, generated fixture, complete exporter, or parity claim
applies. Independent review is owner-waived under the recorded project policy; no reviewer is
claimed.
