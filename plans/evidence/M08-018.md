## What was done

Six new tests in the test module of `crates/ti4-policy/src/bot.rs`, all red-first where a
behavioral claim is made:

1. **`an_unlimited_action_window_re_offers_the_same_scorer_until_decline_or_exhaustion`** —
   one player, two eligible action-timing secrets (`fwp` feat-based + `ans` requirement-based),
   `AnyPerPlayer`. Asserts the window re-offers the same scorer after each score (two offers,
   both to the same seat) and closes only on decline. Pins M06-021a's unlimited-window shape at
   the bot boundary.
2. **`a_one_per_player_combat_window_scores_each_secret_once_and_never_re_offers`** — two
   players each holding `fwp`, one occurrence, `OnePerPlayer`. A cold (argmax) bot scores both;
   asserts exactly one offer per player and that the window closes without re-offering. Pins the
   combat/invasion cap at the bot boundary.
3. **`an_agenda_window_scores_every_eligible_secret_and_closes`** — agenda-timing secrets
   (`fwp` + `ans`) under `AnyPerPlayer`; both scored, then decline closes the window.
4. **`a_player_with_no_eligible_secret_is_skipped_not_asked`** — a seat whose only secret is
   status-timing gets no ask at all (window skips it), and its bot records zero decisions.
5. **`a_retained_combat_pause_scores_the_attacker_s_own_secret_and_resumes_to_victory`** — the
   M07-022-style fixture (destroyer vs fighter+cruiser, system "18") with a `ScoredBot` holding
   `fwp`. The barrage kills the defender's last fighters; the occurrence is consumed and its
   scoring window serviced exactly as `Game` does; the bot scores its own secret at the pause;
   combat resumes to attacker victory. Asserts: outcome, feat on the attacker, empty hand, VP > 0,
   and that the context table stayed unasked (M07-023 Q2 guard).
6. **`scored_games_stay_legal_and_deterministic_across_nested_windows`** — the campaign: 10 seeds
   × 3 faction rotations × 2 runs = 60 full six-player games (~86 s), one `ScoredBot` per seat on
   the sim's accepted wiring (derived per-seat seeds, POK scope). Asserts per run pair: identical
   replay records (legality + determinism); every offered secret alias in a scoring record belongs
   to that player's final hand or scored set (redaction at the bot boundary); and non-vacuity —
   at least one score offer and at least one same-player re-offer occurred across the campaign.
7. **`scoring_explanations_name_no_secret_the_seat_does_not_own`** (added during review, U1) —
   explanation-layer guard: every token in `Decision::explain()` that resolves as a secret
   objective must be one the seat owns. See "Review resolutions" below.

## Findings and design decisions

- **No engine or policy production defect found.** The revalidation's purpose was to catch M06/M07
  regressions in bot observation; none required a fix. All six tests pass against unmodified
  production code (engine suite count unchanged: 847 + 5 doctests).
- **Alias-space collision (test-design lesson, not an engine finding).** The first draft of the
  campaign's redaction invariant flagged `bot p3 was offered the secret sar it does not own`. A
  probe (`crates/ti4-policy/examples/probe_leak.rs`, created and deleted after use) showed the
  offending record was a **research choice** offering `sar` — which is both the WARFARE technology
  *Self-Assembly Routines* (technologies.json) and the secret objective *Spark a Rebellion*. Alias
  spaces collide across content categories. The invariant was corrected to inspect scoring-window
  records only (`prompt == "score an objective"`), where every non-decline option is an objective by
  construction; public/secret objective aliases were verified collision-free (none in corpus). The
  engine offered nothing it should not have — p2 legitimately scored `sar` as its own secret, and the
  research offer was a technology. Recorded so the invariant's scope is never "fixed" back to an
  all-records check.
- **Seed 51 for the retained-pause test.** `Dice::from_faces` is engine-test-only; the policy crate
  must use natural seeds. A probe over seeds 1..60 found seed 51 gives the required shape: round-1
  barrage kills the defender's last fighters (pause), then attacker wins after resumption. The test
  asserts `paused == true` so a future dice-stream change that breaks the fixture fails loudly
  rather than silently losing coverage.
- **Configuration coverage.** Default temperature for the campaign and focused tests; cold/argmax
  for the OnePerPlayer test (deterministic argmax makes the exactly-once assertion exact). All
  focused tests use `remembering()` bots so decision logs are inspectable. POK source scope is the
  accepted ScoredBot configuration on this branch (sim wiring); FULL-scope bot play is not an
  accepted configuration here and was not exercised — recorded, not deferred work.

## Review resolutions (Tier B, Claude Opus 5 — `plans/M08-018_OPEN_REVIEW_ITEMS.md`)

### U1 (LOW) — explanation layer untested: resolved with a guard test + structural argument

The reviewer's structural argument is recorded here in full: every component name in the policy
scoring layer is a **static string literal** (`Components::of("victory", …)` etc. across
`bot.rs`/`scoring.rs`) — no `format!`-built or alias-derived name exists, so an explanation cannot
carry an alias today. But `Decision::explain()` (scoring.rs) prints every **option id** as a
standalone token, and in scoring windows option ids *are* objective aliases — verified by the
probe output below. The argument therefore protects only the component names; the id surface was
live but unpinned.

New test `scoring_explanations_name_no_secret_the_seat_does_not_own` (bot.rs test module): drives
the real two-secret action window with a remembering bot, then asserts that **every token in every
explain() output that resolves as a secret objective is one the seat owns** (still holds or has
scored). Token-based matching avoids substring false positives; scoping to scoring decisions avoids
the ML-3 cross-category collision (a research decision's `sar` is a technology, not an offer of
the secret).

Non-vacuity probe (temporary inversion of the assertion, then restored): with the check inverted
to `!owned.contains(token)`, the test failed immediately — proving the scan finds aliases in real
explain() output:

```
thread 'bot::tests::scoring_explanations_name_no_secret_the_seat_does_not_own' panicked at bot.rs:2029:
explain() names the secret btv the seat does not own:
a — score an objective
*   100.00  btv  [victory=+100.00]
    100.00  dtgs  [victory=+100.00]
test result: FAILED. 0 passed; 1 failed;
```

Restored assertion re-run green. (The panic message reads "does not own" because the inverted
probe asserts the negation — `btv` is in fact owned and scored by the seat.)

### U2 (LOW) — alias collision is a systemic corpus property: recorded as ML-3

Added **ML-3** to `plans/KNOWN_DIFFERENCES.md`: aliases are unique within a content category, not
across them. Verified counts re-scanned for this package (not copied from the review):

- Singular `alias` field only: **6** collisions (`crisis`, `nm`, `obsidian`, `sar`, `te`, `vpw`).
- All four identifier fields (`id`/`alias`/`aliases`/`aliasList`), excluding planets/systems:
  **23** collisions.
- Intra-file duplicates: none. Public∩secret objective aliases: empty (40 vs 40).

The reviewer's count of "27" was not reproducible under any definition tried; its four cited
examples (`galvanize`, `mirage`, `mr`, `crisis`) are real collisions and are named in ML-3. The
reproducible counts above are the standing record.

### U3 (INFORMATIONAL) — policy suite 0.12 s → ~86 s: closed by operator, no action

Operator-reviewed 2026-08-22: the cost does not reach training (`#[cfg(test)]` only; rollout
binaries never build the test harness); 60 full games at ~1.4 s each is proportional to what the
test now plays (the suite went from playing zero games to sixty). Accepted as recorded in this
evidence's "Behavior change" section.
