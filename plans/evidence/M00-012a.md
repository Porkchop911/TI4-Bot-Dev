# M00-012a — Fixed warmup protocol

Every benchmark case runs 10 unmeasured warmup iterations, followed by a five-second idle period
before timed samples begin. A warmup is invalid if the workload errors, produces a semantic-mismatch
marker, or changes its checked input hash. Warmup output is not aggregated and is retained only in
the local raw report. The protocol does not attempt a JIT-stability threshold: Rust and CPython do
not share one, and an open-ended warmup makes results incomparable.

The benchmark runner must create fresh game/workload state per iteration unless the workload
explicitly measures clone/fork. It must seed each iteration from the manifest-defined seed, never
ambient entropy. No CPU power-plan, priority, or affinity setting is changed by the runner.

**Status:** superseded draft replaced by fixed M00-012 protocol; no benchmark measurement claimed.
