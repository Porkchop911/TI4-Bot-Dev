# M03-007c — Native semantic replay

## Active package specification

| Field | Value |
|---|---|
| Parent / dependencies | M03-007; M03-007a parser and M03-007b checksummed corpus are complete. |
| Objective | Consume the captured explicit decisions and dice entropy with a native Rust game and prove the same canonical state/event projection. |
| Python sources | `tools/oracle_exporter/runner.py::{_scenario_game,bounded_game_records,replay_records}`; `tools/oracle_exporter/projections/{state,event}.py`; `engine/game.py::seated_game`; `engine/sim.py::{save_52_galaxy,save_54_galaxy}`. |
| Permission | P0 read-only inspection of the pinned oracle and existing Rust code. No P1 implementation was started because the required compatibility boundary is absent. No network, P2 generation, ports, destructive action, or external-state change. |
| Compatibility required | Exact selected-option order and dice entropy consumption, then semantic equality of the exported canonical state/event projections. |
| Non-goals | Treating a parser success, source replay, same seed, partial game run, or aggregate outcome as native parity. |

## Blocking evidence

1. Each retained header identifies a `save52` or `save54` source scenario. The exporter constructs those specific maps through `save_52_galaxy` or `save_54_galaxy`, while Rust `Game::new` accepts a prebuilt Rust `GameState` and has no corresponding Save 52/54 scenario constructor or map projection importer.
2. `BoundedTrace` deliberately preserves only selected option IDs and dice-roll history. Its M03-007a contract intentionally ignores source state, event, and outcome records. Native replay therefore has no source-projection input to compare unless a new, versioned state/event translation boundary is implemented.
3. Rust `Game` currently drives legal choices generated from its own partial state machine. It has no scripted source-option compatibility adapter; accepting the captured IDs without proving they were offered by the native game would violate the choice legality boundary.
4. Rust `Dice` derives faces from native `GameRng` (ChaCha domain streams) and exposes no checked injected entropy stream. Reusing the Python source seed would be expressly non-equivalent, and overwriting resulting dice history would not make gameplay consume that entropy.
5. Source events are resolved records with numeric IDs, canonical payloads, cancellation, phase, turn, and round. The game driver records `Vec<String>` labels, so it cannot produce the required source-equivalent event projection. The typed timing model does not currently own game-driver event emission.

## Decision

No replay adapter, permissive choice lookup, synthetic dice history, or projection shim was added. Any such implementation would create apparent success while leaving the required semantic comparison unproven.

The direct technical prerequisites are a versioned source-scenario/state importer or native Save 52/54 builders, checked injected entropy, a legal scripted-decision adapter, and unified canonical game event/state projection. Those belong to the generic-game and compatibility work that M04/M00 must establish.

## Milestone-order blocker

The plan declares M03 as a gate before M04, but this split child explicitly depends on generic-game parity. The repository has partial M04 work, yet it does not supply the four required compatibility surfaces. Advancing M04 to resolve the dependency would violate the stated strict M03-before-M04 execution rule unless that ordering exception is approved and recorded.

## Status

**Blocked. No implementation was safe to commit.**
