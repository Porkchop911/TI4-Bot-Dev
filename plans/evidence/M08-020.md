- Spec: `plans/M08-020_GROUND_COMBAT_STRUCTURE_LEGALITY.md` (scoped by the M07-020 frontier
  adjudication of F-M07-019-1, option 2; see `plans/M07-020_OPEN_REVIEW_ITEMS.md` R1 and
  `plans/evidence/M07-020.md`).
- Branch: `wp/m08-020-ground-combat-structure-legality`, base commit `734de3f` (M08-017 closure).
- Review tier per spec: **C — frontier model** (legality/timing semantics of invasions, per
  AGENTS.md escalation rule).
- Normative source: FFG *Living Rules Reference 2.0* rule 49 ("If a player lands units on a planet
  controlled by an opponent but that does not contain any of the opponent's ground forces, that
  planet falls without resistance") and rule 42 (ground combat: only ground forces roll and take
  hits). Verified against the official rules during M07-019; re-cited here unchanged.

## What was done

All production changes in `crates/ti4-engine/src/invasion.rs` (+392/−82 across both files under
`crates/`; game.rs is test-module-only, +84 lines of diff). Five coordinated changes:

1. **New helper `ground_force_owners(state, content, sources, system, planet)`** — returns the set
   of players holding units on the planet whose type satisfies `UnitType::is_ground_force()`. This
   is exactly the corpus predicate for "participates in ground combat": infantry/mech roll 1 die;
   PDS and Space Dock have no `combatDieCount`/`combatHitsOn`; the Titans' PDS (`titans_pds2`) is
   a structure that is also a ground force. **Verification scope (corrected per review T2):**
   checked against four records — infantry, pds, spacedock, titans_pds2 — all of which the
   predicate already classifies correctly; the claim as originally written ("corpus-verified")
   overreached, because it did not check `titans_pds` (Hel-Titan I), which sits adjacent in
   `units.json`, rolls a die at 7, carries the corpus's own `isGroundForce` flag, and is **missed**
   by the predicate. The corpus flag is never read anywhere in the codebase; the full flag-vs-
   predicate comparison (45 flagged / 1 missed / 2 unflagged-but-matched Naaz space mechs) and the
   resulting defect are recorded as finding T1 → KD-5, scoped as M08-022. The same predicate the
   codebase already uses for "who holds a planet" in `establish_control` (49.5) and `landable`.

2. **Trigger (`advance_fighting`)** — replaced `defender_on` (any rival unit ⇒ contested) with:
   fight only where the invader has ground forces on the planet AND a rival player has ground
   forces there. A structure-only planet is skipped straight to control transfer. The old
   `defender_on` method was deleted (single caller).

3. **Casualty pools** — both removal paths now offer only ground forces:
   - window path `remove_ground`: pool filtered by `is_ground_force()` (was `.first()` of *any*
     unit, so a PDS stored before infantry died on the first hit);
   - standalone API `ground_combat` → `absorb_ground`: same filter (was any unit).

4. **Fight termination** — both the window path (`resolve_ground_round`) and the standalone
   `ground_combat` now end the fight when one side has no *ground forces* left, not when its last
   unit of any kind falls. Without this, a mixed planet whose rival ground forces were all killed
   would keep "fighting" against surviving structures (defender rolling 0 dice) — in the window
   path indefinitely, since that loop is choice-driven and has no round cap.

5. **Structure destruction on capture (`finish_control_gain`)** — after L1Z1X Assimilate runs
   (unchanged ordering: "converts … before anything else looks at what is standing on it"), all
   remaining rival structures on the captured planet are destroyed. `finish_control_gain` is the
   single chokepoint for both control-gain paths (immediate and post-pause resume), so the sweep
   covers every capture in the invasion flow. Enemy ground forces cannot be present at that point:
   the invader holds the planet only because every rival ground force is dead (or was never there).

**Tests:**

- New `invasion.rs::a_structure_only_planet_falls_without_resistance` — full window flow,
  structure-only planet (pds + spacedock): asserts no "fight" prompt is ever offered, **no
  ground-combat dice are consumed** (`dice.rolled("ground combat").is_empty()`), the planet is
  captured with `previous = Some(holder)`, and only the invader's infantry remain — rival
  structures destroyed on control transfer.
- New `invasion.rs::structures_survive_a_legitimate_ground_fight_and_die_when_control_changes` —
  mixed planet (pds stored first, then one infantry; invader two infantry; faces `[10, 8, 1]`;
  rival home set so the combat win pauses the invasion): asserts at the combat-win pause that **the
  PDS still stands owned by the rival** (it survived the fight), and after completion that it is
  gone — destroyed when control changed hands, not by a hit.
- Re-pointed `game.rs::the_home_loss_pause_holds_the_invasion_at_finalizing_control` per spec item
  4 / M07-019 review M1c: the fixture's planet now falls without resistance (no ground-combat
  occurrence exists), so the test consumes the home-loss occurrence directly after `drive`, keeps
  the pause-ordering assertions (control transferred before the pause; capture exactly once;
  resume to done), and makes the conversion assertions load-bearing — at the pause b's three
  structures still stand unconverted (6 units total on the planet); after the resume they are
  converted one-for-one (pds×2 → pds×2, spacedock×1 → spacedock×1) with nothing left rival-owned.

## Design decisions

- **`finish_control_gain`, not `establish_control`, hosts the destruction sweep.** Assimilate must
  run before anything else looks at the planet (documented ordering, M07 faction work), and it runs
  only in `finish_control_gain`; putting the sweep inside `establish_control` would destroy
  structures before Assimilate could convert them. Both capture paths (immediate and post-pause)
  funnel through `finish_control_gain`, so one site covers all of them.
- **M1c correction — "l1z1x_ variants" was a misnomer.** The spec's item 4 said the ownership
  assertion should check for l1z1x_ variants. Corpus verification shows L1Z1X has **no structure
  variants**: its unit list is `fighter, destroyer, cruiser, carrier, l1z1x_dreadnought,
  l1z1x_flagship, infantry, l1z1x_mech, pds, spacedock` — the structures are generic. Assimilate's
  `faction_unit(content, "l1z1x", "pds")` therefore resolves to the generic `pds`, and converted
  structures come back as **generic pds/spacedock owned by the invader**, never with an l1z1x_
  prefix. A prefix check would be vacuous (the exact defect class M07-019's review caught). The
  strengthened assertion instead pins one-for-one base-type count preservation (pds×2 → pds×2,
  spacedock×1 → spacedock×1) plus invader ownership — which is what "load-bearing conversion
  assertions" requires. Recorded here as a spec-wording correction, not a scope change: the intent
  (M1c's Assimilate-after-pause coverage) is fully met and stronger than the letter.
- **Supply sufficiency in the game.rs fixture.** L1Z1X starts with one PDS and one spacedock
  (`startingFleet "dn, cv, 3 ff, 5 inf 0,sd 0,pds 0"`); plastic caps are pds=6, spacedock=3.
  Remaining at conversion: 5 ≥ 2 and 2 ≥ 1 — all three conversions succeed, so one-for-one holds
  without supply interference. (The `assimilate_stops_at_the_box` test in faction_abilities.rs
  covers the capped path separately.)
- **Standalone `ground_combat` fixed for consistency.** It is pub API with no production callers
  today (tests only), but it shares the defect; leaving it inconsistent would let a future caller
  reintroduce KD-2 through the public surface. Its existing test (`ground_combat_ends_with_one_
  side_holding_the_planet`, infantry-only) still passes unchanged.

## Findings ledger

- **T1 (MEDIUM, resolved by scoping — see review file):** the package makes `is_ground_force()`
  load-bearing, and that predicate misses `titans_pds` (Hel-Titan I) in favor of a hardcoded id.
  Dormant under D11's roster (Titans off-roster); fires on any widening. Recorded as **KD-5** in
  `plans/KNOWN_DIFFERENCES.md`; fix scoped as **M08-022** with the Naaz space-mech decision
  carried into its spec (a bare flag read would drop two units the base-type match catches).
  No code change made here — `ti4-content` is outside this package's writable paths.
- **T2 (LOW, applied):** the "corpus-verified" claim above was selective in exactly the place
  that mattered; corrected to state what was checked and what the flag actually says.
- **T3 (informational, recorded):** defender selection in `ground_combat` changed shape — from
  first unit found on the planet to the first element of a `BTreeSet<PlayerId>` of ground-force
  owners. Both are deterministic; the set is sorted by `PlayerId`, arguably more deterministic than
  storage order. In a three-way contest the chosen defender could differ from before; no rule
  governs the choice and no test depends on it.
- **F-M08-020-1 (informational, deferred):** `bombardment_at` targets *any* rival unit on a planet
  (`defenders = on_planet(planet).filter(owner != invader)`), so bombardment can destroy structures
  and its `BombardedOutTheLastGroundForces` feat counts them in `held`. Per LRR 49.1 bombarding
  ships fire at **ground forces** below; structures are not valid targets (a PDS's planetary shield
  is what blocks bombardment, which the engine already models separately). Same defect class as
  KD-2 but a different rule step with its own feat interaction — out of this package's scope by
  design (spec non-goals: "no changes to … bombardment"). Deferred; if M08-018/021 bot work shows
  it matters, scope a follow-up before M08-019 closes. No behavior change made here.

## Behavior change and known-differences impact

- **KD-2 is fixed.** `plans/KNOWN_DIFFERENCES.md` KD-2 updated from open to resolved by this
  package. Observable changes: structure-only planets no longer consume dice or "fight a round"
  choices; in mixed fights structures survive the combat and die at control transfer (or are
  converted by Assimilate first); L1Z1X Assimilate is now reachable through `InvasionWindow` for
  structure-bearing captures.
- **Baseline comparability.** Every M08 baseline built before this commit (M06-closure mean VP
  2.958/seat; the M08-017 gate re-run) ran on pre-fix invasion behavior. Per the hard ordering,
  M08-018's post-M07 bot revalidation and M08-021's distribution baseline are the first numbers
  computed on corrected behavior; they must not be compared against pre-M08-020 numbers without
  this note. No VP/clearance measurement is made in this package (no bot work — spec non-goal).
