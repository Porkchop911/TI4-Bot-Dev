# M00-009e — Executable resolved-event projection

## Package specification

- **Milestone/package:** M00-009e, event projection implementation; dependency M00-007d.
- **Objective:** Project an oracle event only after its timing windows resolve, including its stable
  UID, cancellation state, normalized payload, and game phase context.
- **Oracle sources/tests inspected read-only:** `engine/timing.py`, `engine/game.py`, and
  `tests/test_choice.py` at `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 oracle inspection; P1 writes limited to
  `tools/oracle_exporter/`, `tools/test_oracle_state_projection.py`, this evidence file, and
  `plans/EXECUTION_STATE.md`. No network, external state, or oracle writes.
- **Inputs/outputs:** a resolved oracle `Event` and its current `GameState` in; a deterministic,
  JSON-ready event object out.
- **Compatibility class:** exact for `Event.type`, `payload`, `cancelled`, and `uid`; semantic for
  the captured game context because the future exporter decides which state boundary to observe.
- **Explicit non-goals:** intercepting the resolver, building the chronological stream, CLI/NDJSON
  framing, outcome/error projection, fixture generation, and parity claims.

## Implementation

- Added `tools/oracle_exporter/projections/event.py` and exported `event_projection`.
- Projection captures the oracle's actual `Event` fields (`type`, `payload`, `cancelled`, `uid`),
  plus `GameState.phase`, `turn_seq`, and `round`. It is documented for use after the resolver's
  WHEN/AFTER windows because either can mutate payload or cancellation state.
- Reuses the choice projector’s strict recursive JSON normalizer: maps have sorted string keys;
  sequences retain order; unsupported values are refused instead of stringified.
- Focused tests cover context/UID/cancellation preservation, nested payload ordering, byte-identical
  JSON, and unsupported-payload refusal.
