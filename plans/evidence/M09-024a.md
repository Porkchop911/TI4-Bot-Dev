## Design decisions worth a reviewer's attention

**Why the key and not insertion order.** Reordering columns invalidates every weight and every
Adam moment at once. Ordering by `FeatureKey` — a pure function of the name — means input order
cannot reach the output, so a discovery pass may run in any order on any number of threads and two
builds still agree byte for byte.

**The `*-unit` family.** The explicit grammar admits a bounded `<canonical-kind>-unit:` suffix
rule whose left half varies with the choice kind, so those families cannot be enumerated. They
share one reserved column rather than being denied one and silently pooling into the global OOV.
This is a judgement the plan does not make; it is called out because a reviewer might prefer either
per-kind columns (unbounded) or the global fallback (lossier).

**Validation at load.** `from_json` checks that every stored key is the key of its own name, that
no two columns share a key, and that the assigned columns fit the recorded capacity. A vocabulary
this module built satisfies these by construction; one read off disk was *stored*, possibly by
another version, and the properties every trained weight depends on are worth one pass to confirm.
This is also what makes the collision branch reachable end to end.

## Limitations — stated, not hidden

1. **The collision branch is tested through the loader, not through `build`.** A real 64-bit
   FNV-1a collision cannot be constructed in a test at any affordable cost. Rather than adding a
   key-injection seam that exists only for the test, the branch is reached the way it is genuinely
   reachable end to end — a stored `slots.json` claiming one. The `build`-time collision check is
   therefore covered by inspection, not by measurement. Recorded rather than glossed, because
   "covered by inspection" is exactly the standard M08-019 Y1 found insufficient; the difference
   here is that the property is unreachable by any test, not merely untested.
2. **`V_cap` is provisional.** 53,248 covers the r6 names plus reserved columns. 024b will grow it.
3. **No zeroing assertions.** §4.5 requires that rows `slot_count..V_cap` and their Adam moments
   are zeroed, masked from optimization, and asserted zero at save/load. Those live on the tensor,
   which does not exist until M09-025/026 — this package fixes the capacity that makes them
   meaningful and does not implement them.
4. **The `*-unit` shared column is a judgement.** See above.

## Independent Tier-C review of `c3d5514` (2026-08-25)

**Verdict: changes required.** Two HIGH schema findings block M09-024a:

1. `OOV_REGISTRY_VERSION = 1` does not freeze a version-1 layout. The reserved order is rebuilt
   from mutable feature-family lists and sorted, so a new family can move existing OOV columns
   without a version bump; the current coverage test would endorse rather than reject that drift.
2. `from_json`/`validate` do not verify registry version, exact reserved prefix/`oov_count`, global
   OOV presence, or capacity limit/granularity. Public mutable schema fields and unchecked public
   `reindex` also allow callers to bypass invariants after load.

Independent gates are green: vocabulary **12/0**, full policy **148/0**, scoped Clippy/rustfmt and
diff-check clean. The r6 union independently reproduces **41,113** with every recorded per-faction
count exact. Green gates do not cover the stale-version or malformed-layout cases. Full findings
and required corrections: `plans/M09-024a_OPEN_REVIEW_ITEMS.md`.

M09-024a remains open; M09-024b may not begin on this frontier.
