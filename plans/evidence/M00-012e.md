## Variance thresholds

### Acceptable variance
| Metric | Max std dev (% of mean) | Max p95-p50 (% of mean) |
|---|---|---|
| Single-core game | 2% | 5% |
| Fixed-worker throughput | 3% | 8% |
| Policy scoring | 5% | 10% |
| Snapshot/fork | 5% | 10% |
| Stage 2 training | 10% | 20% |
| Peak memory | 15% | 25% |

### Rejection criteria
- If variance exceeds threshold: rerun with 2x iterations.
- If variance still exceeds threshold after rerun: flag as "unreliable" and investigate.
- Unreliable benchmarks must be excluded from performance gates until resolved.

### Performance gate thresholds (from master plan)
| Metric | Required (min) | Target | Stretch |
|---|---:|---:|---:|
| Single-core four-round game | 3x | 5x | 10x |
| Fixed-worker throughput | 3x | 5x | 10x |
| Policy scoring | 3x | 6x | 12x |
| Snapshot/fork | 3x | 5x | 10x |
| Stage 2 training throughput | 2x | 4x | 8x |
| Peak memory per worker | no regression | 40% lower | 60% lower |

### Gate enforcement
- No performance result counts unless semantic parity tests for that workload pass.
- All benchmarks must pass variance thresholds before comparison is recorded.
- If variance is unreliable, the benchmark result is "pending investigation" — not a pass or fail.
