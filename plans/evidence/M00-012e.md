# M00-012e — Variance and performance-gate policy

| Workload | Maximum sample stdev / mean | Maximum p95 − p50 / median |
|---|---:|---:|
| Single-core game, policy scoring, snapshot/fork | 5% | 10% |
| Fixed-worker throughput | 8% | 15% |
| Training throughput | 10% | 20% |
| Peak memory | 15% | 25% |

If either threshold fails, repeat one fresh 30-sample interleaved run. If either run passes, retain
both reports and mark the result `unstable`; it cannot support a performance gate. If both fail,
mark it `rejected_variance`. Never combine runs or cherry-pick samples.

A speedup is reportable only when both reports pass the workload's semantic gate, use the same
fixture/seed/worker policy/host fingerprint, meet the variance thresholds, and retain raw samples.
The master-plan gates remain: 3× required for single-core, fixed-worker, policy, and snapshot;
2× for training; no memory regression. This document establishes procedure only and reports no
performance result.
