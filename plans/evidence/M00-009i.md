# M00-009i — Bounded-game oracle observation

## Package specification

- **Milestone/package:** M00-009i, prerequisite split for M00-010; dependency M00-009h2.
- **Objective:** Capture the oracle's generated choices, post-resolution events, final state, and
  seeded dice history for a bounded game without mutating the oracle or converting an incomplete
  game into a successful outcome.
- **Oracle sources/tests inspected read-only:** `engine/game.py`, `engine/timing.py`,
  `engine/choice.py`, `engine/dice.py`, `engine/sim.py`, and replay tests in
  `tests/test_combat.py` / `tests/test_factions.py` at the pinned commit.
- **Permission class:** P0 oracle inspection; P1 writes limited to `tools/oracle_exporter/`, the
  focused exporter test, this evidence file, and `plans/EXECUTION_STATE.md`. No network, output
  artifacts, or oracle writes.
- **Compatibility class:** semantic trace observation. Resolved events are captured only after
  their timing windows; bounded horizons remain visibly unfinished unless the oracle really ends.
- **Explicit non-goals:** fixture corpus generation, replay execution, full timing-start ordering,
  or a Rust/Python parity claim.

## Implementation

- Added `tools/oracle_exporter/runner.py` with deterministic Save 52/54 base and full-source
  scenario constructors.
- A recording table preserves every legal choice projection together with the selected stable
  option ID. A per-game `_emit` observer captures each resolved `Event` only after oracle timing
  windows complete.
- The record begins and ends with canonical state. Dice history is emitted explicitly with seed,
  faces, hit threshold, and sorted reroll positions. An outcome exists only when the oracle state
  is actually finished.

## Compatibility and review

Events are appended when resolution returns. Nested emissions therefore appear in completed
depth-first order, with the oracle's monotonic event UID retained; this is a resolved-event trace,
not a speculative event-start trace. Setup-time events are not reconstructed because the oracle
does not retain their objects. Independent review is owner-waived; no reviewer is claimed.
