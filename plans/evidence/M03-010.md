## Invariants and compatibility contract

- `emit` runs WHEN, ordinary resolution, then AFTER. A cancellation during WHEN or a matching
  persistent cannot cancels the event before ordinary resolution and suppresses AFTER.
- Action/status windows use initiative order rotated from the active player. Strategy/agenda
  windows use seating order rotated from the speaker, with initiative fallback when seating is
  absent.
- Each player resolves at most one ordinary ability per pass. A pass is cleared after any ability
  resolves so later information reopens that player's opportunity.
- Candidates are filtered by exact event/relation, owner, in-window use, and optional condition;
  generated choices retain the event type and rule-provided factual payload.
- Every invalid decider answer returns `TimingError::IllegalChoice`; no invented option executes.
- Frequency metadata remains registered but intentionally unconsumed until M03-012. A repeatable
  slot therefore needs a changing rule condition in this package; M03-012 supplies broader scope
  consumption before content registers reaction-card slots.

## Tests added

1. WHEN resolves before ordinary event resolution and AFTER.
2. Action priority rotates initiative from the active player.
3. Agenda priority rotates seating order from the speaker.
4. Each player takes only one ability before the next pass.
5. A player who declines is reoffered after another player resolves.
6. WHEN cancellation skips ordinary resolution and AFTER.
7. A persistent cannot cancels before ordinary resolution and AFTER.
8. An invented optional-ability choice is returned without executing that ability.

## Implementation and compatibility evidence

- `Resolver::emit` records an event trace, runs the correctly partitioned WHEN candidates, checks
  cancellation and persistent cannot effects, performs ordinary resolution, then runs AFTER.
- Candidate lists are clones of the ordered registry entries before any mutable resolver/table
  borrow. This preserves registration order while allowing a selected effect to mutate the event
  or recursively call the resolver in M03-011.
- Window priority rotates a list rather than sorting players. The window's per-pass resolved and
  passed collections are ordered sets, never hash tables.
- Optional selections go through `Table::ask`, inheriting the common validation and append-only
  decision log. A single mandatory candidate bypasses an artificial decision exactly as the oracle
  does.
