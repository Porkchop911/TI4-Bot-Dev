## What this package did

1. **F1 (carried blocking finding from M06-023 independent review): fixed and regression-tested.**
   `combat.rs::note_holdings` built note issuers with `PlayerId::new(issuer)` where the key suffix
   is a faction name, so faction-note issuers could never match any seat; only Support-for-the-Throne
   entries fired. Both space (`BeforeCombat.notes`) and ground (`invasion.rs`) Betray-a-Friend paths
   consume this one snapshot, so the single fix covers both emitters. Issuers now resolve through
   `promissory::owner_of` + `promissory::seat_of`; unseated owners yield no issuer (no phantom ids).
   Lookup direction (`notes[winner].contains(loser)`) was verified against the printed card and left
   unchanged. A defect-class sweep found no other occurrence: `laws.rs::repeal`'s
   `PlayerId::new(owner)` is correct because law targets are stored as player ids in this engine.
2. **F2 (new blocking finding): recorded and escalated to child package M06-025.** baf and sb print a
   play-area restriction the engine does not enforce, and the face-up model hard-codes two aliases
   while the accepted corpus marks eleven notes `playArea: true` (eight faction notes uncovered).
   Complete fix exceeds atomic review-fix scope; spec written at
   `plans/M06-025_PLAY_AREA_NOTE_SCORING.md`. **Blocks the M06 exit gate.**
