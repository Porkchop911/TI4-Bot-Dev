## Implemented behavior

- `Game` owns `GameState`, `Table`, the decision log, deterministic observable event names, the
  original strategy-card set for later rounds, and an open structural secondary window.
- `legal_options` returns generated strategy/action/secondary choices without mutating state.
  `step` asks the table, validates through the existing choice boundary, and resolves exactly one
  player decision; automatic window and phase work is reported with `resolved_choice = false`.
- Strategy drafting, structural strategic primaries, each follower secondary, passes, turn changes,
  action-phase entry, and empty-agenda round rollover are driven through the owner. Event names are
  recorded in order for replay observation.
- `StepResult` exposes phase, active player, finished state, typed error metadata, and whether a
  player decision was resolved. `run(rounds, max_steps)` returns the state or a typed step-limit /
  blocked-step error instead of looping indefinitely.
- Status bookkeeping and agenda reveal are invoked only at their structural boundaries. Required
  yet unimplemented decisions (status scoring/token allocation; agenda voting/ties/effects) stop
  with explicit `GameError` metadata and remain blocked without further mutation. No default votes,
  token pools, scores, tactical actions, component actions, or Fleet Logistics behavior were added.

## Compatibility and review

The driver mirrors the oracle's generated-choice / one-step / bounded-run architecture, but it
intentionally cannot claim end-to-end parity: the Rust rules tree has no implementations for the
mandatory status and agenda decisions. Unlike the stale documentation this replaces, an incomplete
run is visible as a typed error rather than an apparent successful round. There is no differential
exporter yet (M00-009 remains open), so this is source-and-decision-boundary evidence, not a parity
claim. No benchmark applies.

Independent package review is owner-waived under the project execution policy; no reviewer is
claimed. M04-013 may use `Game`, `Table`, and the explicit stopped-run result for the random-legal
bot without fabricating an unavailable action.
