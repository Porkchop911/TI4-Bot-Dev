# M00-009g — Executable deterministic error projection

## Package specification

- **Milestone/package:** M00-009g, error projection implementation; dependency M00-007f.
- **Objective:** Preserve an oracle exception and explicit game context in a replayable record
  without treating the failure as success or adding nondeterministic machine data.
- **Oracle sources/tests inspected read-only:** `engine/choice.py`, `engine/game.py`,
  `engine/timing.py`, and `tests/test_choice.py` / `tests/test_game.py` at
  `37061c511a4780d4c0719e0342533a498cd4b457`.
- **Permission class:** P0 oracle inspection; P1 writes limited to
  `tools/oracle_exporter/`, `tools/test_oracle_state_projection.py`, this evidence file, and
  `plans/EXECUTION_STATE.md`. No network, external state, or oracle writes.
- **Inputs/outputs:** an exception, oracle `GameState`, and optional player/option/card identifiers
  in; a deterministic JSON-ready error object out.
- **Compatibility class:** semantic. Exception class/message and game context are preserved;
  stack traces are deliberately omitted because paths and frames are not deterministic portable
  compatibility data.
- **Explicit non-goals:** swallowing/recovering from exceptions, wrapping the game loop, CLI/NDJSON
  framing, fixture generation, and parity claims.

## Implementation

- Added `tools/oracle_exporter/projections/error.py` and exported `error_projection`.
- Each record has exact exception class name/message plus `turn_seq`, round, phase, active or
  supplied player, optional choice/card IDs, and `stack_trace: null`.
- Exception capture remains the caller's responsibility: this function creates an evidence record
  but does not alter or suppress the original failure.
- Tests cover an `IllegalChoice` with full context, byte-identical runtime-error output, and refusal
  of invalid optional context types.

## Compatibility and review

The old M00-009g draft proposed `traceback.format_exc()`. That output contains environment-specific
paths and call stacks, so it cannot satisfy the mandatory byte-identical exporter invariant. The
structured record is retained and the trace is explicitly null. No benchmark, generated fixture,
complete exporter, or parity claim applies. Independent review is owner-waived under the recorded
project policy; no reviewer is claimed.
