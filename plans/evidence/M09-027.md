## What was built

`crates/ti4-policy/src/critic.rs`, a namespace disjoint from the policy's:

```rust
pub fn critic_facts(seen: &Observed<'_>, player: &PlayerId,
                    enabled: CriticFeatures,
                    held_secrets: &[CardProgress]) -> Vec<(String, f64)>
```

**The signature takes no `Choice`.** That is the load-bearing part: §4.1 excludes the prompt, the
option id/kind/payload, the target, the legal-option count and aggregates, anything derived from
iterating the legal set, authored valuations, scoreable-count helpers, and future outcomes. A
function that cannot see the legal set cannot depend on its order or its contents, so the exclusion
is enforced by the type rather than by an inventory someone has to keep honest. Every name is in the
single `critic-state:` family.

`Actor::value(&self, critic: &SparseOption, row: FactionRow) -> Result<f64, ActorError>` runs the
same trunk over that vector with the same selected `emb[f]` row M09-026 pinned, and a `[width]`
value readout.

`Observed::phase()` was added to `crates/ti4-engine/src/choice.rs`; the phase is a public fact and
§4.1's option-free base needs it.

## The three properties (§4.2)

`crates/ti4-mlp/tests/critic_invariance.rs`. The first two say `V` does not depend on the legal set.
The third exists because **a model that ignores option features entirely satisfies both** — so
invariance alone would pass a broken model, and the policy is checked for the opposite property on
the same shuffle.

| Property | Result |
|---|---|
| critic vector and `V` invariant to legal-set order and contents | pass, exact (`< f64::EPSILON`) |
| `V` non-vacuous on the fixture | pass, `V != 0` asserted |
| the policy **does** follow the same shuffle | pass |

## Two ways the third test passed for the wrong reason first

Recorded because both are the defect class this milestone keeps producing: a gate that cannot fail.

**The fixture made the options indistinguishable.** The vocabulary was synthetic
(`option:name0..599`), so every real emitted name fell to its family's OOV column and all three
options collapsed onto the same columns. The policy came out uniform, and the non-vacuity guard —
`spread > 1e-9` — passed on f32 accumulation noise: `p` and `q` were bit-identical while
"differing" by 2e-6. The vocabulary is now built from the names the position actually emits, and
non-vacuity is checked on the **inputs** (the three options must occupy different columns), because
checking only that the outputs differ numerically is what let noise through.

**The tolerance was unachievable.** The assertion was `< 1e-12` on values a f32 trunk produced.
Reordering options re-associates the sums behind each logit and behind the softmax normaliser;
measured disagreement is ~5e-7 on probabilities near 0.5. The bound is now `1e-5`, and it is not a
number tuned until the test passed: when the fixture genuinely broke the property the two
distributions differed by the whole mass (0.049 against 0.498), five orders of magnitude away.

**Falsification.** With a position bias `+0.01·i` injected into `probabilities`, the third test
fails and the first still passes; source restored byte-identically
(`sha256 60775889a964572b…` before and after).

## Measured gap — recorded, not fixed here: M09-027b


The family is in neither `OOV_FAMILIES_V2` nor `FAMILY_ROLES`, so `column_of` falls through to
`GLOBAL_OOV_COLUMN` and the whole critic vector sums onto column 0. **`V` is therefore a rank-1
projection of the position plus the faction embedding, not a critic.** The namespace and the
invariance properties this row asks for are correct and tested; the value it currently computes is
not useful until the names are reachable.

discipline), a `FamilyRole` for the family, the corpus emitting critic names, and one regenerated
768-game generation — two more crates and a republish. `PI_WORK_PACKAGE_STANDARD.md` says to split
when work crosses crate boundaries, and to record the child **before** implementing it, so
**M09-027b** is in the milestone table and **M09-028 now depends on 027b** rather than on 027.
