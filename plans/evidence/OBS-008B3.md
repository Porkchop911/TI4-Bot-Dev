## Result

1. **The gap.** Before this package, `announce_retreat`'s "stay"/"retreat" options and
   `retreat_to`'s destination options carried **no payload at all** — not even the generic
   board-fact pipeline (`option-system:*`) reached them, since that pipeline only fires when an
   option names a `system`. These three option kinds were the only combat producers exposing
   nothing beyond option ID and label.
2. **Engine.** `Announcing`: "stay" and "retreat" (or the forced "retreat" alone) now carry
   `system` (the combat system) and a `ShipsInSystem` preview. 78.7's "retreat the whole remaining
   fleet together" rule makes this exact and simple: "retreat" previews the asking seat's own ship
   count there falling to zero; "stay" previews no change. `Retreating`: each destination option
   carries `system` (that destination) and a `ShipsInSystem` preview — the seat's own count
   already there, to that count plus the whole retreating fleet's size, read once per choice via
   `ships_of` rather than once per option.
3. **Board context restored for free.** Attaching `system` also activates the pre-existing,
   already-approved `option-system:*` family through `structured_features`'s generic tail — no
   further wiring needed, the same mechanism `OBS-008b1`'s `unit` payload activated for
   `casualty-unit`.
4. **Policy.** `combat_decision_features`'s subtype guard now matches `announce_retreat` and
   `retreat_to`; a `ShipsInSystem -> "ships"` arm joins the existing `Certain`-outcome delta match,
   sharing the `combat:ships-{before,after,change}` names between the departure and arrival facts.
   No new family, no vocabulary bump.

## Focused evidence

- `combat.rs::obs008b3_retreat_options_preview_the_whole_fleets_arrival`: a hub fixture with the
  defender's two fighters in the combat system and two eligible retreat destinations already
  holding 1 and 3 of the defender's own fighters respectively. "stay" previews `ShipsInSystem`
  `2 -> 2`; "retreat" previews `2 -> 0`; both carry `system`. Each destination previews its own
  existing count rising by the whole retreating fleet's size (`1 -> 3`, `3 -> 5`), and carries
  `system` for that destination.
- `features.rs::obs008b3_retreat_options_carry_subtype_and_exact_ship_counts`: the same shape
  built directly as two `Choice`s. `combat:subtype:announce_retreat`, `combat:option-count` (2),
  and `combat:ships-change` (-2, with the genuine-zero `ships-after` a dropped sparse entry) reach
  the policy from the "retreat" option; "stay" carries `ships-before`/`ships-after` (2/2) with a
  dropped `ships-change` (a genuine zero); a `retreat_to` destination option carries
  `combat:subtype:retreat_to` and exact `ships-{before,after,change}` (1/3/2), which survives
  `mlp_option_features` and `projection::admits`.
